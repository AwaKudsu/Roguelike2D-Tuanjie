## 1. 射手被挂毯挡住（bug 1）

大厅（`Assets/_Project/Scenes/Game.unity` 里的 `LobbyRoom`）是三座石台 + 一块挂毯。
三座台按 0.5 / 空间均分摆在 x = 4.6 / 10.0 / 15.4，**中间那座正好是射手**；
挂毯挂在 (10, 8.5)，3.37 × 2.53 单位，覆盖 y = 7.24 ~ 9.76。

| 物体 | sortingOrder | 结论 |
| --- | --- | --- |
| 挂毯 Banner | **-160** | 画在最前面 → 挡人 |
| 台座 Stand | -170 | 被挂毯挡 |
| 立绘 Portrait | -169 | 被挂毯挡 |
| 石台光圈 Glow | -180 | 更后面 |

射手立绘是 2×3 单位、轴心在正中、贴在 (10, 7.12)，即 y = 5.62 ~ 8.62；
挂毯从 7.24 往下压 —— **正好压在头上**。

**改法**：把挂毯的 `sortingOrder` 从 -160 改成 **-176**，落在「光圈(-180) 之后、台座(-170) 之前」。
SpriteRenderer 的先后只由 sortingOrder 决定，改一个数就够了，位置不用动
（不动位置的好处：挂毯仍然贴着后墙，三座台也不用重新排版）。

- 场景：`Game.unity` → `Banner/SpriteRenderer.m_SortingOrder = -176`
- 生成器：`_Tuanjie/Editor/LobbyRoomBuilder.cs` 里同步改成 -176，否则重跑一次生成器又会被改回去

## 2. 怪物抠图（bug 2）

### 根因：老导入器只认「一个」底色

`_Tuanjie/Editor/EnemyFrameImporter.cs` 的做法是：
取**左上角那一个像素**当背景色，容差 90（曼哈顿距离 = |Δr|+|Δg|+|Δb|），从四边泛洪。

哥布林和骷髅弓箭手的截图底色是图片编辑器的**透明棋盘格**：白 `(255,255,255)` 和灰 `(192,192,192)` 交替。
两者差 63×3 = **189**，远超 90 —— 所以**只抠掉了一半格子**，另一半原样留在图里。
到了游戏里再被预制体的绿色染色一乘（见 2.3），就变成了截图里那块「绿色马赛克」。

> 另外四只（史莱姆 / 蝙蝠 / 火焰法师 / 持盾战士）的背景是游戏里的深绿房间，同一个颜色，
> 所以老办法能抠个大概 —— 但容差 90 太宽，会把人物身上偏暗的描边也一起吃掉。

### 改法：`Tools/enemy-art/rekey_enemy_frames.py`

1. **从四边聚类出全部底色**：把边框上的颜色按出现次数聚类，取占比 ≥6% 的几类。
   棋盘格会聚成两种（白 / 灰），纯色底只有一种。
2. **棋盘格单独判**：两种底色亮度差 ≥40、且都是中性色时，认定是棋盘格。
   此时判据换成「中性色 + 足够亮」（灰格子、白格子、以及它们中间那圈过渡灰全算背景）。
   ★ 关键是**保留暖色**：哥布林挥砍那一帧的刀光是奶白偏黄（r-b 有 20 多），
   如果只看亮度，那半个弧会被当成背景一起抠掉（第一版就是这样，图 2 第 2 张）。
3. **从四边泛洪**：只清「和画布边缘连得上」的背景像素。人物内部的同色像素
   （牙齿、眼白、刀光内圈）被深色描边包着，泛洪进不去，天然保住。
4. **补一刀「被包住的小块背景」**：胳膊和身体之间的缝隙里露出的格子，泛洪进不去，
   按「颜色本来就是底色 + 连通块面积很小」补清。
5. **去掉贴边碎块**：源截图里常常切到隔壁那只怪的一角，
   规则是「不连通主体 + 摸到画布边 + 面积 < 主体 25%」。
6. **尺寸一个像素都不改**：PPU 是按「这张图多高」反算的，改尺寸等于改大小。
   工具里会断言「源图尺寸 == 工程里那张的尺寸」，不一致就报错跳过。

![怪物抠图前后](images/24-enemy-art.png)

用法（改完素材、或者以后换素材时）：

```powershell

& $py Tools\enemy-art\rekey_enemy_frames.py --dry-run     # 只算不写，看报告

& $py Tools\enemy-art\rekey_enemy_frames.py --out 临时目录 --sheet 临时目录   # 先出对比图
```

### 顺带修的：给贴图染色

`_Tuanjie/Editor/EnemyBuilder.cs` 建预制体时给 `SpriteRenderer.color` 填了一个「区分用的颜色」
（哥布林是 `(0.45,0.72,0.35)`）。那是给**白色占位方块**上色用的；
一旦换成真贴图，这层颜色会把整只怪染绿 —— 棋盘格被抠掉之前，那些灰格子也被乘成了绿色。

改法三处，缺一不可：

1. 预制体：六个 `Resources/Enemies/*.prefab` 的 `m_Color` 全部改成 `(1,1,1,1)`；
   `m_Sprite` 也从占位方块换成各自待机第 0 帧（编辑器里预览、真没配帧时也不会是白框）。
2. 代码：`EnemyController.Awake` 里，只要 config 配了帧，就把颜色强制回白色
   （老预制体、以后新加的怪都不会再被染色）。
3. 生成器：`EnemyBuilder` 不再传 tint，永远写白色。

## 3. 方块怪（bug 3）

房间预制体（`Prefabs/Rooms/Room_01.prefab`、`Room_02.prefab`）里躺着的「怪」是
**没挂 `EnemyConfig` 的 `EnemyController`** —— 也就是迁移期那套「一个方块 + 颜色」的占位怪。
上一轮虽然把六只怪的预制体和配置都做好了，但**没有任何房间把它们摆进去**，
所以游戏里跑的还是那三个方块（截图里的紫色方块就是哥布林位那个占位怪）。

**改法：把占位怪就地升级成「刷怪点」，运行时换成真怪。**

- `Room.Awake`：扫到「有 EnemyController 但没有 config」的子物体 → 记成刷怪点，
  立刻关掉它的贴图和碰撞体（避免闪一帧方块 / 挤到刚刷出来的怪）。
- `Room.Start`（在数人头之前）：按本局种子从怪物池里抽真怪，生成在刷怪点脚下，
  登记进 `_enemies`（这样「清光敌人才开门」照样成立），最后销毁占位怪。
- 占位怪改名 `EnemySpawn_0/1`，y 从「方块中心」改成「脚踩地面」的高度
  （怪物贴图轴心在脚底，不改会浮空 —— 史莱姆和蝙蝠不受重力，会一直漂着）。

### 为什么怪物池走 Resources

`Assets/_Project/Resources/Enemies/*.prefab`，用 `Resources.LoadAll<GameObject>("Enemies")` 收。

原因是团结（Tuanjie）给新资产的 `.meta` 里存的是**加密形态的 GUID**
（56 字符 base64，例如 `DX0d5i7+Unuu7xUaXyaAcAyMnqt3jd0+/HAsQ1WtdIeKIwpZrVvSI4w=`），
而场景/预制体里的引用仍是 32 位 hex —— 两者只有编辑器自己能对上，手写引用等于赌。
`Resources.LoadAll` 按文件夹收，一个 GUID 都不用写；以后加第七只怪，
把预制体扔进这个目录就自动进池子。

## 4. 每局随机刷怪（bug 4）

| 规则 | 值（`Room` 组件的字段） |
| --- | --- |
| 开随机刷怪 | `spawnRandomEnemies = true` |
| 每个刷怪点起步 | 1 只 |
| 从第几间开始变多 | `extraFromRoom = 3` |
| 每几间多一只 | `extraStepRooms = 2` |
| 一个点最多几只 | `maxPerPoint = 3` |
| 多出来的怪左右散开 | `scatterX = 1.2` |
| 精英房 | 额外 +1（上限仍受 `maxPerPoint` 约束） |

于是：第 1~2 间 = 每个点 1 只；第 3~4 间 = 2 只；第 5 间起 = 3 只。

**随机要能复现**：种子 = `RoomManager.RunSeed × 31 + 房间号 × 977`
（`RoomManager.RunSeed` 是新加的属性，保证随机源在使用前已经建好）。
同一个种子跑两次，每一间刷出来的怪、站位都一样 —— Console 里那行
`[RoomManager] 本局种子 = …` 填回 `Seed` 就能重放。

**同一间房尽量不重复**：抽怪不是每次独立摇，而是先把池子洗牌，再按顺序取，
取完一轮才回到开头。所以六个刷怪点会尽量把六只怪各来一遍。

## 5. 怪跑到「通关柱子」后面（bug 5 · 追加）

用户截图：房间里一扇锁着的门（那根 1×4 的长柱子，`lockedColor` 灰蓝），
门**右边**站着一只骷髅弓箭手，门左边是持盾战士 —— 近战职业绕不过去，
门又锁着（要清光敌人才开），于是整间房卡死。

门锁着的时候是一面**实心墙**（`Door.ApplyState` 把 collider 设成非触发器），
怪正常走不过去；但两件事会让它出现在门后：

1. **刷怪点太靠门**：一旦某个房间的刷怪点摆在门的外侧，开局就在门后；
2. **被挤过去**：弓箭手的 AI 是「玩家靠近就后退」，它退到门口被门顶住，
   后面再有别的怪（史莱姆、持盾战士都爱往玩家身上贴）顶它一下，
   两个刚体会互相挤，夹在 1 单位厚的门里就可能被解算到外侧去。

改法两条，一条堵来源、一条兜底：

```csharp
// ① 刷怪位置先收到门的这一侧（门内侧再留 doorClearance = 1.6）
Vector3 origin   = ClampInside(marker.transform.position);
Vector3 position = ClampInside(origin + new Vector3(offset, 0f, 0f));

// ② 门还锁着的时候，每 0.35 秒检查一次：有怪站到门另一侧就拉回来
if (behindDoor) { body.position = rescued; body.velocity = Vector2.zero; ... }
```

![刷怪安全区](images/25-spawn-safe-zone.png)

- 判定只用「门相对出生点在哪一侧」：`DoorSide = sign(门.x − 出生点.x)`，
  安全线 = `门.x − DoorSide × doorClearance`。房间把门摆在左边也照样成立。
- 没有门的房间（纯奖励房）不做任何限制。
- 兜底只在**门锁着**时生效；门开了玩家自己就能走过去，不用管。
- 拉回时会打一条 `[Room] xxx 跑到门后面了（门还锁着），已拉回房间内侧 x=…` 的 Warning，
  以后再出现能立刻在 Console 里看到。
- 顺带把六只怪的刚体从 `Discrete` 改成 `Continuous`：持盾战士冲撞 9 单位/秒、
  蝙蝠俯冲 10 单位/秒，门只有 1 单位厚，离散检测本来就可能「穿过去」。
  连续检测按扫掠算，成本可以忽略，穿墙/穿门这类事故从源头少一大半。

可调字段（`Room` 组件）：

| 字段 | 默认 | 作用 |
| --- | --- | --- |
| `doorClearance` | 1.6 | 刷怪点离门至少留这么远（单位） |
| `keepEnemiesInside` | true | 门锁着时把门后的怪拉回来 |
| `insideCheckInterval` | 0.35 | 多久查一次（秒） |

## 8. 怎么验证

### 8.1 不开编辑器就能验的

```powershell
# 1) 两个程序集能不能编过（团结自带 Roslyn，不启动编辑器）
powershell -ExecutionPolicy Bypass -File Tools\archer-port\compile_check.ps1 -Project <工程绝对路径> -Csproj Assembly-CSharp.csproj
powershell -ExecutionPolicy Bypass -File Tools\archer-port\compile_check.ps1 -Project <工程绝对路径> -Csproj Assembly-CSharp-Editor.csproj -SkipRefName Assembly-CSharp -ExtraRef Temp\_check\Assembly-CSharp.dll

# 2) 素材有没有抠干净（边框一圈不许有不透明像素）
& $py Tools\enemy-art\rekey_enemy_frames.py --dry-run

# 3) 刷怪点有没有落在门的另一侧（用房间真实坐标算）
& $py Tools\room-spawn\verify_spawn_zones.py --verbose
```

### 8.2 在编辑器里按 Play 要看的几件事

1. **大厅**：三座台上的人都在挂毯**前面**，射手的头完整（对照 `docs/images/24-lobby-banner.png`）。
2. **进第一间房**：Console 出现 `[Room] Room_01（战斗）：敌人 1 个，门锁着`，
   画面里站着的是六只怪之一（不是方块），**身上没有发绿/发红**。
3. **打死它**：门开；进第二间（Room_02）应该有 2 只怪。
4. **打几间**：第 3 间开始一间房 2~4 只，第 5 间起更多；同一间房间里不出现重复品种。
5. **门的另一侧不许有怪**：站在门口往两边看，怪的 x 都在门的内侧；
   如果 Console 出现 `跑到门后面了…已拉回` 的 Warning，说明兜底被触发过（不卡死就是对的）。
6. **重放**：把 Console 里的种子填回 `RoomManager.Seed` 再 Play，
   每一间刷出来的怪应该和上一局一致。

## 9. 已知限制

- 刷怪点仍然是**手摆的固定几个点**（Room_01 一个、Room_02 两个）。
  现在会避开「门的另一侧」，但还没做「避开尖刺 / 避开墙里」的通用选点。
  要更丰富，就在房间预制体里多摆几个空物体 + `EnemyController`（空组件即可），
  或者跑一次菜单 `团结/往房间撒刷怪点`。
- 门只有 1 单位厚，理论上多只怪一起挤还是可能把某一只能挤过去 ——
  所以留了第 5 节那条兜底（门锁着时每 0.35 秒检查、把门后的怪拉回门内侧），保证房间不会卡死。
- 怪物强度（血量/攻击）还是 `EnemyConfig` + `CharacterStats` 里的老数值，这次没动平衡。
- 素材是「截图 → 抠图」，边缘仍有一点点背景色残留（火焰法师的火球外圈最明显）。
  要彻底干净只能重画或要原始 PNG，工具这边已经做到「背景色像素全清」。
