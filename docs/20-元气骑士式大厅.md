# Day 20 · 元气骑士式等待大厅（俯视版）

> 大厅是一间**俯视的、略暗的房间**：两条角色立牌摆在台上，鼠标点一下弹出确认框，
> 确认之后人物才出现、才能四方向走动，走到门口就开局。
> 关卡本身仍然是**横板**（重力、跳跃、冲刺都在），进关时换回横板控制器。

---

## 1. 玩起来是什么样

```
        ┌──────────────────────────────────────────────────┐   ← 四面墙，走不出去
        │  ░░░            ░░░            ░░░              │
        │                                                  │
        │     ╔═══════╗       ╔═══════╗                    │
        │     ║ 战士  ║       ║ 法师  ║         ┌────┐      │
        │     ╚═══════╝       ╚═══════╝         │ 门 │      │
        │            ╭─ 出生点 ─╮               └────┘      │
        └──────────────────────────────────────────────────┘
     世界坐标 x = -70（房间内部 0~20 宽、0~10 高）
```

1. 按 Play → 进大厅，房间里只有两个发光的立牌，**玩家是隐藏的**（还没选人）
2. 鼠标移到立牌上 → 光圈变亮、立牌放大；点一下 → 弹出确认框（职业名 + 技能表）
3. 点「确认」→ 人物按这个职业出现，可以 `WASD` 四方向走动（俯视，没有重力）
4. 走到门口 → 门板亮起，按 `E`（或直接站在门口 0.8 秒）→ 建第一间房、切回横板

## 2. 为什么俯视大厅 + 横板关卡共存

| 问题 | 处理 |
| --- | --- |
| 大厅要四方向走动，关卡是横板带重力 | 大厅期间**关掉** `PlayerController`（重力/跳跃/冲刺/攻击判定），换成 `LobbyAvatar` 用速度直接驱动刚体；出门时再开回来 |
| 确认前不能让玩家动，但玩家就在场景里 | 进大厅先把玩家 `SpriteRenderer` 藏起来、`LobbyAvatar` 关掉 —— 人物看不见也走不了，确认后才显形 |
| 鼠标点选要精确到「人」 | 立牌先看**立绘包围盒**（点身体任何位置都算中），再退一步看脚底半径 1.1 的圆 |
| 大厅比关卡需要看得更多 | 相机**从玩家身上摘下来**、放到房间正中，再按房间尺寸和窗口比例算正交大小（宽屏按宽算、窄屏按高算），出发时挂回玩家并还原 5.0 |
| 大厅里不该在建房 | `RoomManager.SuspendForLobby()` 让它待命（清房间、`RoomsCleared` 归零），出门 `StartRunFromLobby()` 再建第一间 |
| 大厅里不该有血条 | 进大厅关掉 HUD 的 `Canvas`，出门打开（那套 HUD 坐标是按关卡算的，在大厅既没用又挡视线） |

**仍然在同一个场景里**（`Assets/_Project/Scenes/Game.unity`），没新建 `Lobby.unity`：
玩家是场景内物体、不是预制体，新场景要么复制一份玩家（两份以后必然走样），要么先把玩家做成预制体（改动面很大）。

## 3. 代码结构

| 文件 | 职责 |
| --- | --- |
| `Assets/_Project/Scripts/Lobby/LobbyRoom.cs` | 大厅主控：`Selecting / Walking / Left` 状态机、鼠标点选、确认框、走到门口出发 |
| `Assets/_Project/Scripts/Lobby/LobbyPedestal.cs` | 角色立牌：职业数据、立绘、光圈、呼吸动画、`HitTest` |
| `Assets/_Project/Scripts/Lobby/LobbyAvatar.cs` | 俯视走路：速度驱动刚体、四方向、按 Y 排 `sortingOrder` |
| `Assets/_Project/_Tuanjie/Editor/LobbyRoomBuilder.cs` | 菜单 **团结 → 生成元气骑士式大厅**：搭房间、立牌、门，写引用进场景 |
| `Assets/_Project/_Tuanjie/Editor/LobbyRoomCheck.cs` | 菜单 **团结 → 验证元气骑士式大厅**：36 项自检 |

关键入口：

```csharp
// GameBootstrap.HandleScene()
if (ShowLobbyOnStart) _lobby.Enter();   // 进大厅
else                  _lobby.Leave();   // 直接开局（第二局、返回大厅重载时）

// LobbyRoom
public void Enter();          // 停建房 / 关横板组件 / 藏起玩家 / 移到出生点 / 相机摘下来对准房间正中
public void Pick(int index);  // 鼠标点中立牌 → 弹确认框
public void ConfirmPick();    // 装职业 → 显示玩家 → 打开俯视走路
public void Leave();          // 还原一切 → StartRunFromLobby() → 移到关卡出生点
```

相机取景不是写死一个 size，而是按房间尺寸算：

```csharp
float halfWidth  = roomSize.x * 0.5f + cameraMargin;   // 10 + 1.2
float halfHeight = roomSize.y * 0.5f + cameraMargin;   //  5 + 1.2
float aspect     = Mathf.Max(0.5f, camera.aspect);
camera.orthographicSize = Mathf.Max(halfHeight, halfWidth / aspect);
```

16:9 的窗口算出来 6.2（可视 26.8×12.4），4:3 的 Game 视图算出来 8.4（可视 22.4×16.8），两种比例都装得下整间房。
写死 6.0 时 4:3 下左右各被切掉约 2 个单位 —— 墙都看不见，这就是「拍照只拍到房间中间一截」的原因。

`RoomManager` 的两个大厅接口：

```csharp
public void SuspendForLobby()    // _suspended = true；销毁房间；RoomsCleared 归零
public void StartRunFromLobby()  // _suspended = false；真的建第一间（房间池 + 种子 + 移动玩家）
```

`Start()` 里加了 `if (_suspended) return;` —— 否则进大厅的瞬间会先建一间房再被收掉，白算一次种子。

## 4. 两个坑

### 4.1 读键盘不能用老的 `Input`

第一版写 `if (Input.GetKeyDown(KeyCode.E))`，自检直接抛：

```
InvalidOperationException: You are trying to read Input using the UnityEngine.Input class,
but you have switched active Input handling to Input System package.
```

本工程是 **Input System Package**，老接口一调就抛。改成新接口并做空判断（批处理里没有键盘）：

```csharp
Keyboard keyboard = Keyboard.current;
return keyboard != null && keyboard.eKey.wasPressedThisFrame;
```

### 4.2 俯视时人物前后要分清楚

横板只有一条地面线，`sortingOrder` 常量就行；俯视有前后，站得靠下的人要挡住靠上的。

```csharp
_sprite.sortingOrder = Mathf.RoundToInt((sortBaseY - transform.position.y) * 6f);
```

`sortBaseY = 10f`（房间上沿），所以 y 越小（越靠下）`sortingOrder` 越大，看起来就在前面。

## 6. 排错表

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 按 Play 直接在关卡里 | `ShowLobbyOnStart` 被上一局置 false 且没重载域 | 已由 `GameBootstrap.ResetStatics()`（`SubsystemRegistration`）每次 Play 重置 |
| 大厅是空的 | 没跑 **团结 → 生成元气骑士式大厅** | 跑一次 |
| 看到大厅但人物站在关卡里 | `LobbyRoom` 的 `spawnPoint` 没接 | 重跑生成菜单 |
| 点立牌没反应 | 立牌 `classData` 为空，或 `pickRadius` 太小 | 重跑生成菜单；或调大 `LobbyRoom.pickRadius` |
| 确认后还是走不了 | `LobbyAvatar` 没挂在 Player 上，或被别的脚本关了 | 看 Player 上有没有 `LobbyAvatar`，`IsActive` 是否为 true |
| 人物被墙挡住走不动 | 墙在 `Ground` 层且带碰撞（这是故意的） | 门口留了缺口；房间出口就是 `Portal` |
| 出发后站在房间里没怪 | `RoomManager` 仍 `_suspended` | 检查 `Leave()` 有没有被调用 |
| 人物前后遮挡不对 | `sortBaseY` 与房间上沿不一致 | 调 `LobbyAvatar.sortBaseY`（默认 10 = 房间上沿） |

## 7. 已知限制

1. 大厅和关卡在同一个场景，`Game.unity` 变大；Hierarchy 多一支 `LobbyRoom`。
2. 只有两个职业台；加职业要重跑生成菜单（或复制台子再拖 `ClassData`）。
3. 提示文字是屏幕空间 Canvas（中文字形只能运行时加载动态字体），不跟人物走。
4. 大厅没有独立 BGM / 音效（工程还没有音频素材）。
5. 「返回大厅」是重载场景，会看到一帧黑。
6. 出发键写死 `E` / `Enter` / 手柄 A，没进改键界面。
7. 俯视走路没有八方向斜跑的独立动画帧，复用横板的跑动帧（左右翻面）。
