# Day 20 · 元气骑士式等待大厅（俯视版）

> 大厅是一间**俯视的、略暗的房间**，铺满整个画面：两个角色站在石台上，鼠标点一下弹出确认框，
> 确认之后**台上那个人就活过来变成你**（不是凭空冒出一个角色），才能四方向走动，走到门口就开局。
> 关卡本身仍然是**横板**（重力、跳跃、冲刺都在），进关时换回横板控制器。

---

## 1. 玩起来是什么样

```
   ┌──────────────────────────────────────────────────────────┐
   │  ▓▓▓                                                      │
   │  ▓▓▓        ╔═════╗            ╔═════╗                    │  ← 上墙 + 挂毯
   │    ▲        ║ 战士 ║            ║ 法师 ║      ▲            │    火把 / 石柱
   │            └─────┘            └─────┘                    │
   │           ╭──────────── 地毯 ────────────╮                │
   │           ╰─────────────────────────────╯                │
   │                        ┌──────┐                          │  ← 门（确认后亮起）
   │                        └──────┘                          │
   └──────────────────────────────────────────────────────────┘
     世界坐标 x = -70（房间内部 0~20 宽、0~10 高；地板比房间多铺一圈）
```

1. 按 Play → 进大厅，画面被房间**铺满**（没有天空色、没有血条）
2. 房间里站着两个人（战士 / 法师），鼠标移上去 → 光圈变亮、立牌略放大
3. 点一下 → 弹出确认框（职业名 + 介绍 + 技能表），点「确认」
4. **台上被选中的那个人消失、玩家出现在他站的位置** —— 雕像解除、你接管这个角色
5. `WASD` 四方向走动（俯视，没有重力）→ 走到门口，门亮起 → 按 `E`（或站 0.8 秒）开局

## 2. 三条设计取舍

### 2.1 为什么大厅是「俯视」而关卡是「横板」

| 问题 | 处理 |
| --- | --- |
| 大厅要四方向走动，关卡是横板带重力 | 大厅期间**关掉** `PlayerController`（重力/跳跃/冲刺/攻击），换成 `LobbyAvatar` 用速度直接驱动刚体；出门再开回来 |
| 两个原版角色的美术是**横板侧视**的 | 立绘照用（本来就是玩家要选的角色），房间与家具全部另行绘制（§3），侧视人物站在俯视地板上是像素游戏通行的做法 |
| 不能凭空冒出一个人 | 确认时不移动角色到出生点，而是**把玩家挪到选中台子的脚下**、并把该台子的立绘收起 —— 看到的是同一个人解除雕像状态 |

### 2.2 画面比房间大一圈，镜头跟着人走

相机在大厅里从玩家身上摘下来：**选人时**放在房间正中，正交大小固定 `lobbyCameraSize = 6`；
**确认之后**（`Stage.Walking`）每帧朝人物的位置靠一点 —— 但先被 `ClampCameraToFloor` 夹一次：

```csharp
_camera.transform.SetParent(null, true);
_camera.transform.position = new Vector3(roomCenter.x, roomCenter.y, _cameraPositionBefore.z);
_camera.orthographicSize = Mathf.Max(0.1f, lobbyCameraSize);   // 6 → 16:9 下画面 21.3 x 12
```

```csharp
// 相机矩形必须整块落在地板里：地板外面是相机底色，露一点就穿帮
float loX = min.x - floorPadding.x + halfW;
float hiX = max.x + floorPadding.x - halfW;
float x = hiX >= loX ? Mathf.Clamp(wanted.x, loX, hiX) : (min.x + max.x) * 0.5f;
```

`6` 比房间高度的一半（5）大一点，所以**房间里的一切都在画面里**，四周还留一圈地板；
地板铺 30 × 17（房间 20 × 10 外面各多 5 / 3.5），`floorPadding` 就是这一圈 ——
跟随的幅度全靠它撑出来：人从台子（y ≈ 6.3）走到门口（y = 1）时，相机在 y 2.5…7.5 之间移动。

- 16:9 → 画面 21.3 × 12：整间房 + 外圈地板
- 4:3 → 画面 16 × 12：左右墙贴边，上下仍是房间 + 地板
- 超宽屏：画面比地板还宽时 `ClampCameraToFloor` 让相机退回房间正中（宁可不动，也不露底色）

### 2.4 灯光挂在火苗上，再用遮罩剪在房间里

光斑就是 `LobbyGlow.png` 放大出来的（1 单位软光斑 → `localScale` 4.5）。两件事决定它好不好看：

1. **中心要对准火苗**。火把贴图 32×72 @55 PPU ≈ 1.3 单位高、中心对齐，火苗在中心**上方 0.4**，杆在下方。
   所以 `Light_Left/Right` 的位置是 `(2.9, 8.5)` / `(17.1, 8.5)` —— 与火把同一个 x，y 抬 0.4。
   放在火把中心（8.1）时，最亮的一圈其实落在杆上，看上去像地板上凭空多了一团光。
2. **不能穿墙**。4.5 单位的光斑挂在 y = 8.5，有一半越过上墙（y 9…10）糊到墙外的岩石上。
   `SpriteRenderer` 没有裁剪，用一块 **SpriteMask** 把光剪在房间内：

```csharp
// LobbyRoomBuilder.BuildLightMask：一块和房间（20×10）一样大的遮罩
mask.sprite = sprites["LobbyBackdrop"];   // 不透明贴图顶替；遮罩自己不渲染，拉多大都看不出来
mask.isCustomRangeActive  = true;         // 只作用于排序落在这一档的渲染器
mask.backSortingOrder     = -199;         // 地板 -200、地毯 -185、石台光圈 -180 都不受影响
mask.frontSortingOrder    = -190;

// 灯光自己声明「只在遮罩里画」
renderer.maskInteraction = SpriteMaskInteraction.VisibleInsideMask;
```

于是光只画在房间矩形内，墙外是干净的暗岩石；墙砖（-150）本来就在光的上面，
看上去就是「光被墙挡住了」。

代价：房间外的地板不会再被灯照亮（这正是想要的）。以后要是想让光透到走廊，
就把一块遮罩拆成房间 + 走廊两块。

### 2.5 四方向朝向：给正/背视图留的插槽

大厅是俯视的，可角色的动画帧是给横板关卡画的 —— **21 张法师帧、27 张战士帧全是侧视**。
于是「往下走」只能拿一张侧视图顶着，看起来像贴着地横着平移。

代码能做的只有「挑哪张图、翻不翻」，画不出正面。所以这里留了三个**可选**插槽：

```csharp
// ClassData
public Sprite lobbyFront;   // 往下走：面对镜头
public Sprite lobbyBack;    // 往上走：后脑勺
public Sprite lobbySide;    // 左右走：侧视，靠 flipX 分左右
```

`LobbyAvatar` 每帧只看输入，不看图存不存在：

```csharp
// 纵向明显压过横向才切 —— 斜着走保持侧视，四方向贴图斜向用侧身最自然
vertical = |move.y| > 0.15 && |move.y| > |move.x| * verticalBias ? (move.y < 0 ? 1 : -1) : 0;
// 1 = 朝下用 lobbyFront，-1 = 朝上用 lobbyBack，0 = 侧视
```

任何一张为空 → 回退到侧视（可翻转），也就是**没有新素材时表现和以前一模一样**，
不会出现「角色变白块」或者「往下走时整个人消失」。

**命名约定**（图和资产用同一个词，不另维护对照表）：

```
Assets/_Project/Art/Characters/<职业>/<职业>_Front.png     → lobbyFront
Assets/_Project/Art/Characters/<职业>/<职业>_Back.png      → lobbyBack
Assets/_Project/Art/Characters/<职业>/<职业>_Side.png      → lobbySide（一般不用，留空即用待机图）
```

画好丢进目录，点菜单 **团结 → 同步大厅朝向图**（`LobbyFacingBuilder`），
它按约定扫文件、写进 `Data/classes/Class_<职业>.asset`；没有的文件跳过，不会清掉手填的。

当前状态：战士的 `lobbyFront` 已经指向 `Warrior_Idle` —— 那张头盔面甲本来就是正对镜头的，
所以战士现在往下走是正的、也不再被镜像；**法师的正/背视图还缺**，三张全空。

还有一件配套的事：`WarriorVisual` / `MageVisual` 的 `Update` 每帧都会
`Apply(ChooseFrame(dt))` 往同一个 `SpriteRenderer` 上写图，跟大厅挑图的逻辑抢帧。
所以进出大厅时 `PlayerVisualSwitcher.SetLobbyMode(bool)` 会把这一职业的关卡动画整个停掉
（`ApplyVisualEnable()` 同时看「是不是大厅」和「是不是法师」两个条件），
出发后再打开 —— 否则大厅里怎么挑图都会被下一帧覆盖回去。

### 2.6 陈设会「自己说」怎么交互

墙根摆了两件中世纪陈设（`BuildProps`）：左边**书架**（纯装饰）、右边**告示板**（技能树）。

交互不是写在大厅里的坐标表，而是每个装饰自带 `LobbyInteractable`：

| 字段 | 作用 |
| --- | --- |
| `prompt` | 底部提示拼成「按 E 查看技能树」 |
| `radius` | 1.6 单位内算站到跟前（`OnDrawGizmosSelected` 会画出来） |
| `title` / `body` | 按 E 后弹出的占位面板内容 |
| `glow` | 靠近时点亮、离开压暗 |

大厅每帧只做一件事：把所有 `LobbyInteractable` 缓存起来、找最近的那个；
站在装饰前时**交互优先于进门**（先 `return`，不再判门口的 E），
避免同一个键在门口附近抢两件事。加第三件装饰不用改大厅代码。

装饰的摆放规则只有一条：**只写在墙根**（`y ≈ 1`）—— 俯视房间里中间要留给走位和两座石台。
`NewProp` 按贴图 `bounds` 把「轴心在中心」的图抬到脚底对齐，排序用和 `LobbyAvatar` 同一套
`(10 - y) * 6`，同深度时压在人后面 1 档。

关键入口：

```csharp
// GameBootstrap.HandleScene()
if (ShowLobbyOnStart) _lobby.Enter();   // 进大厅
else                  _lobby.Leave();   // 直接开局（第二局、返回大厅重载时）

// LobbyRoom
public void Enter();          // 停建房 / 关横板组件 / 藏起玩家 / 立牌复位 / 相机对准房间正中 / 关 HUD
public void Pick(int index);  // 鼠标点中立牌 → 弹确认框
public void ConfirmPick();    // 装职业 → 玩家挪到台子上 → 该立牌 SetAlive(false) → 打开俯视走路
public void Leave();          // 还原一切 → StartRunFromLobby() → 移到关卡出生点
```

`LobbyPedestal.SetAlive(bool)` 只有三件事：`portrait.enabled`、光圈压暗、`Breathe` 跳过 ——
确认后台上不留人，否则会看到两个一模一样的人。

`RoomManager` 的两个大厅接口：

```csharp
public void SuspendForLobby()    // _suspended = true；销毁房间；RoomsCleared 归零
public void StartRunFromLobby()  // _suspended = false；真的建第一间（房间池 + 种子 + 移动玩家）
```

`Start()` 里加了 `if (_suspended) return;` —— 否则进大厅的瞬间会先建一间房再被收掉，白算一次种子。

## 4. 三个坑

### 4.1 读键盘不能用老的 `Input`

第一版写 `if (Input.GetKeyDown(KeyCode.E))`，自检直接抛：

```
InvalidOperationException: You are trying to read Input using the UnityEngine.Input class,
but you have switched active Input handling to Input System package.
```

本工程是 **Input System Package**，老接口一调就抛。改成新接口并做空判断（批处理里没有键盘）：

```csharp
Keyboard keyboard = Keyboard.current;
return keyboard != null && keyboard.eKey.wasPressedThisFrame;
```

### 4.2 俯视时人物前后要分清楚

横板只有一条地面线，`sortingOrder` 常量就行；俯视有前后，站得靠下的人要挡住靠上的。

```csharp
_sprite.sortingOrder = Mathf.RoundToInt((sortBaseY - transform.position.y) * 6f);
```

`sortBaseY = 10f`（房间上沿），所以 y 越小（越靠下）`sortingOrder` 越大，看起来就在前面。

### 4.3 平铺图必须是 FullRect

`SpriteRenderer.drawMode = Tiled` 要求 sprite 的网格是 **Full Rect**；Tight 网格的贴图切到平铺会直接报错。
所以 `ImportSprite` 里显式写了 `settings.spriteMeshType = SpriteMeshType.FullRect`。

## 6. 排错表

| 现象 | 大概率原因 | 怎么办 |
| --- | --- | --- |
| 按 Play 还是在关卡里 | `GameBootstrap.ShowLobbyOnStart` 被上一局改成 false（关掉了「进入播放模式时重载域」） | 已加 `[RuntimeInitializeOnLoadMethod(SubsystemRegistration)] ResetStatics()`，仍不行就重启编辑器 |
| 大厅里一片蓝、房间只占中间一小块 | 相机 size 被场景里的旧值覆盖 | 重跑 **团结 → 生成元气骑士式大厅**（它会把 `lobbyCameraSize` 写成 6） |
| 屏幕边缘露出相机底色 | 地板没铺够 / 相机没对准房间正中 | 同上，重跑生成菜单；用 **团结 → 诊断大厅取景** 看实际数值。地板必须是 30×17，`LobbyRoom.floorPadding` 要与它一致 |
| 走到门口镜头不跟 | `cameraFollowsPlayer` 被关掉、`floorPadding` 太小（可动范围被夹没了），或画面比地板还宽（超宽屏会退回正中） | 看 `lobbyCameraSize` / `floorPadding`；必要时把地板再铺大一圈 |
| 点了角色没反应 | 鼠标射线和立牌不在同一 z，或 `PointerOverUI` 挡了 | 先看确认框有没有弹；再看 `LobbyRoom.pickRadius` |
| 确认后看到两个人 | 选中台子的立绘没关 | `ConfirmPick()` 里应有 `_picked.SetAlive(false)` |
| 大厅里还有血条 | HUD Canvas 没找到 | 重跑生成菜单；`SetHudVisible` 会按 `StatBar` 兜底找 |
| 点确认后角色贴在**上墙**、走不下来 | 地板挂了整间房大小的**实体** `BoxCollider2D`。玩家是 Dynamic 刚体，被送进盒子内部后按最近面向上解穿透，又被上墙（y 9…10）挡住，于是夹在两条边之间 | 地板不该有碰撞体：`LobbyRoomBuilder` 已不再给 Floor 加 `AddCollider`，场景里 Floor 的 `BoxCollider2D` 已删（房间边界交给四面墙）。运行时还有一道兜底：`LobbyRoom.Enter()` 里的 `DisableFloorColliders()` 会把老场景残留的碰撞体关掉并打 `LogWarning` —— 看到这条警告就说明场景还是旧的，重跑生成菜单 |
| 墙上的暖光糊了大半间房 | `Light_Left/Right/Door` 的 `localScale` 是 8、alpha 0.45 | 已改成 4.5 倍、alpha 0.3（门光 0.18），重跑生成菜单或直接改这三个 Transform 的 scale |
| 光斑最亮的地方不在火苗上 | `Light_Left/Right` 的 y 还停在火把中心（8.1），而火苗在中心上方 0.4 | 位置改成 `(火把 x, 8.5)`，重跑 **团结 → 生成元气骑士式大厅** |
| 光透过墙糊在墙外的岩石上 | 没有 `Shell/LightMask`，或者灯没设 `SpriteMask Interaction = Visible Inside Mask` | 重跑生成菜单；遮罩的 custom range 必须盖住 -195（`back -199 / front -190`） |
| 门不亮 / 走不过去 | `portal` 引用断了，或门在墙外面 | 重跑生成菜单；门的世界坐标应是 `(-60, 1)` |

## 7. 已知限制

1. 大厅与关卡在**同一个场景**（`Game.unity`）里，只是隔了 70 个单位 —— 场景里的东西会一直存在
2. 立绘是横板侧视的，转身只是 `flipX`，没有俯视的四方向行走帧
3. 只有两个职业台，加职业要同时改 `LobbyRoomBuilder` 与 `Class_*.asset`
4. 家具（火把/石柱/地毯）是静态图，火把不会跳动、也没有粒子
5. 确认框里的技能表是硬编码的 K/L/U/I 四格，不跟着职业的 `startingSkills` 变
6. 大厅里没有存档/金币/角色解锁逻辑，每次都从两个人里挑
7. 镜头跟随的幅度受房间尺寸限制：房间只有 20×10，比一屏大不了多少，能跟的范围就是多铺的那圈地板（现在约 ±4 单位横向、±2.5 单位纵向）。想要「大半屏都在房间外」的追尾镜头，得把 `RoomWidth/RoomHeight` 一起放大再重跑生成器
8. 法师还没有正/背视图：往上下走时只能拿侧视图顶着（战士的 `Warrior_Idle` 本来就是正面，已经能用）。补图路径见 §2.5
