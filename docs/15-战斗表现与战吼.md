# Day 11 · 战斗表现重做与战吼

> 这一轮是「手感反馈」驱动的改版：把上一版脱手飞出去的刀风换成贴着武器扫的残影，把旋风斩从「一下打完」改成「一直转」，再加一个不打伤害的控制技能——战吼。

## 1. 这一轮改了什么

| 项目 | 之前 | 现在 |
| --- | --- | --- |
| 挥砍弧光 | 弧光脱手往前飞（`SlashWave.cs`） | 弧光贴着武器绕角色扫一道（`SlashTrail.cs`），扫完就消失 |
| 突刺 | 平飞的气刃 | 几乎不扫，只在身前 1.05 单位处闪一下 |
| 旋风斩 | 按下 → 打一个 3.2×2.2 的框 → 结束 | 持续 **1.2 秒**，每 **0.2 秒**扫一次（约 7 下） |
| 技能 2 | 空槽 | **战吼**：巨剑 + 扩散圆环，半径内敌人恐慌 3.5 秒 |
| 跑动 | 4 帧定速 10 fps，0→1→2→3 顺播 | 往复 0→1→2→1，帧率按速度 7~15 fps 自适应 |

## 2. 挥砍残影：为什么不再「飞出去」

飞行刀风的问题不在参数，在于**它描述的动作不是挥砍**：

- 飞出去 = 远程发射，玩家会下意识以为它能打到远处，但伤害只在那一下的判定框里；
- 弧光离手之后，玩家的剑还在原地，视觉和判定脱节。

所以改成「贴着武器扫」：

```
Player（位置跟随角色）
└── __SlashTrail            父物体：只负责绕 Z 旋转 —— 弧光因此绕「角色」转
    └── arc                 子物体：SpriteRenderer，沿朝向偏移 radius
```

父物体只转不位移，子物体偏在 `(±radius, 0)`，旋转父物体时子物体就被「甩」出一个圆弧。这是最省事的绕轴扫法，不用算极坐标。

三段连击各有各的扫法（`PlayerAttacker.PlaySlash`）：

| 段 | 起手角 | 扫过角度 | 半径 | 时长 | 读感 |
| --- | --- | --- | --- | --- | --- |
| 劈砍 | −75° | +135° | 0.55 | 0.18 s | 从头顶那侧往下劈 |
| 上挑 | +105° | −140° | 0.50 | 0.22 s | 从下往上撩 |
| 突刺 | −12° | +24° | 1.05 | 0.13 s | 几乎不扫，往前一闪 |

角度都是「朝右为正」，朝左时 `SlashTrail.Setup` 内部把起点镜像（`180° − startAngle`）、扫描方向取反，所以调用方不用为左右写两套数字。

缓动是 `1 − (1−t)²`（前快后慢）：刀挥出去是「唰」一下，收尾要顿住，匀速会像机械臂。

## 3. 旋风斩：从「一下打烂」到「一直转」

一次性判定有个明显破绽：**敌人在第 0.05 秒之后走进圈里就再也打不到了**。旋风斩应该是「这一段时间里我一直在这儿转」，所以：

```csharp
// SkillCaster.CastMelee
if (skill.duration <= 0f) { attacker.Execute(skill.attack); return; }   // 老的瞬发近战

var spin = GetComponent<WhirlwindCast>() ?? gameObject.AddComponent<WhirlwindCast>();
spin.Setup(attacker, skill.attack, skill.duration, skill.tickInterval, ...);
```

`WhirlwindCast` 只做一件事：每 `tickInterval` 秒调一次 `PlayerAttacker.Execute(attack)`，`duration` 到了就 `Destroy(this)`（只摘组件，玩家不动）。伤害公式、击退、目标层过滤全部复用普攻那份代码，没有第二份伤害逻辑。

旋风的视觉不用它管：判定框面积 7.04 ≥ 6，`PlayerAttacker.PlaySlash` 看到面积够大就会自己放「绕身一圈」的弧光（720° 旋转 + 张开）。

配置在 `Assets/_Project/Data/Skills/Skill_Whirlwind.asset`：

| 字段 | 值 | 说明 |
| --- | --- | --- |
| `duration` | 1.2 | 转多久 |
| `tickInterval` | 0.2 | 每 0.2 秒扫一次 → 约 7 下 |
| `cooldown` / `manaCost` | 4 / 15 | 越久越强，所以冷却比普攻贵得多 |

> 想要「越转越久」的强化，把 `duration` 调大就行，不用改代码。

## 4. 战吼：不打伤害的控制技能

按下 `L`，三件事按时间顺序发生：

| 时间 | 发生什么 |
| --- | --- |
| 0 ~ 0.30 s | 头顶亮出巨剑：0.35 → 0.75 倍、往上飘 1 单位，60% 时开始淡出 |
| 0 ~ 0.45 s | 冲击波圆环从 0.8 单位扩到 `2 × fearRadius`，加速度是 `t²`（先慢后猛扑出去），同时淡出 |
| 0.20 s（圆环过半） | 半径内的敌人全部 `ApplyFear(fearDuration, 玩家位置)` |

**为什么吓人要放在圆环扫到一半**：按下就生效的话，冲击波还在往外走、敌人已经开始跑了，视觉和逻辑对不上，圆环就变成纯贴图了。

美术资源挂在 `Skill_WarCry` 资产上（`ringSprite` / `swordSprite`），都是程序生成的：

- `Assets/_Project/Art/Effects/Ring.png` 128×128，128 PPU → **恰好 1 单位直径**，所以扩到直径 24 单位时 `localScale = 24`，不用换算；
- `Assets/_Project/Art/Effects/GreatSword.png` 64×160，32 PPU → 2×5 单位，缩放 0.75 时约 3.75 单位高，压在角色头顶正好是「巨剑」。

### 恐慌状态机

`EnemyController.FixedUpdate` 的优先级：**死亡 → 硬直 → 恐慌 → 正常 AI**。恐慌期间不追、不打、也不做感知。

恐慌只有三个数字：

```csharp
private float _fearTimer;        // 还剩多久
private float _fearStepTimer;    // 这一小步还剩多久
private int   _fearStepDir;      // 这一小步往哪边跑
```

每 `fearStepTimer` 到点就重挑方向（`BeginFearStep`）：

| 结果 | 概率 | 方向 | 持续 |
| --- | --- | --- | --- |
| 闷头跑 | 62% | 远离玩家 | 0.35 ~ 0.60 s |
| 掉头两步 | 38% | 朝玩家方向冲 | 0.10 ~ 0.20 s |

于是表现是「一直背对着你、来回乱跑，但整体在往远处逃」。如果只会往一个方向跑，看着像被推走；只会原地抖，看着像卡住。

移动速度是 `MoveSpeed × fearSpeedMultiplier`（默认 **2.2 倍**），并且朝向永远跟着这一步的方向 —— 恐慌最直观的信号就是「它一直背对你」。

两点设计取舍：

- **重复施放取 max 不叠加**：`_fearTimer = Mathf.Max(_fearTimer, duration)`。叠加的话连放两次能把敌人永久钉住，那就不是控制技能而是删掉敌人了；
- **恐慌不打断硬直**：硬直在前，恐慌在后。挨打就该先吃硬直，否则「被战吼的敌人还能反击」看起来像 bug。

## 5. 跑动优化

两处改动，都是「素材决定」的：

1. **帧序往复**：素材里 `Warrior_Run_3` 是 `Run_1` 的复制（同一张姿势）。老实 0→1→2→3 播会在 3→0 之间「顿一下」。改成 `RunCycle = { 0, 1, 2, 1 }` 往复播，四个节拍都不重复、循环无缝。
2. **帧率跟速度走**：`Mathf.Lerp(runFpsMin, runFpsMax, |vx| / MaxSpeed)`，慢走 7 fps、全速 15 fps。定速播放在慢速时像原地小跑、全速时像卡住 —— 手感差就是从这里来的。

累加的是「走过几个节拍」而不是时间，所以速度变化时不会跳帧：

```csharp
_runTimer += fps * Time.deltaTime;
int step = (int)Mathf.Repeat(_runTimer, RunCycle.Length);
```

为此把 `PlayerController.MaxSpeed` 从 `private` 改成 `public`（表现层要按「当前速度 / 最大速度」算比例）。

## 7. 排错表

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 挥砍什么都不显示 | `PlayerAttacker.slashArc` 为空 | 跑一次「团结 → 导入战士素材」 |
| 弧光跑到人后面去了 | 分类顺序 / `SortingOrder` | 残影排序 20；比地板（0）高、比 UI 低即可 |
| 弧光往左和往右不对称 | `Setup` 里的镜像被改过 | 朝左走 `180° − startAngle` 且扫描方向取反 |
| 旋风斩还是一下就结束 | `Skill_Whirlwind.duration` 是 0 | 跑「团结 → 生成战斗特效与战吼」 |
| 旋风斩一直扫但没有伤害 | `SkillCaster.CastMelee` 里 `attack` 为空 | 检查 `Skill_Whirlwind.attack` |
| 战吼没有圆环 | `Skill_WarCry.ringSprite` 为空 | 同上，跑装配菜单 |
| 战吼放完敌人照常追 | 敌人距离 > `fearRadius`（12） | 调大 `fearRadius`，或确认敌人在场景里 |
| 敌人恐慌后原地抖 | `fearRunStep` 与 `fearBackStep` 差距太小 | 拉开「闷头跑」和「掉头」的时长差 |
| 跑动帧还是顿 | `RunCycle` 被改回 0→1→2→3 | 素材第 4 帧是第 2 帧的复制，必须往复 |

## 8. 已知限制

- 战吼**没有次数限制**，只受 6 秒冷却与 15 点法力约束，Boss 也能被吓住（以后要加「Boss 免疫恐慌」就在这里加判断）；
- 恐慌只影响移动，**不影响已经出手的攻击**（敌人挥到一半被吓，这一下还是会打完）；
- 圆环是纯色半透明（程序生成），没有做描边或加色叠加；
- 巨剑是程序画的 64×160 贴图，和其他素材的风格不完全统一；
- 旋风斩期间**玩家仍然可以移动**（没有锁位移），这是有意的 —— 锁住会很难受，代价是「转着跑」，等有需要再加 `rootMotion`。
