# 新同学上手指南：从零到能跑

> 目标：让一个**从没碰过这个工程**的同学，在他自己的电脑上把工程跑起来，并且**能提交、能合并、不炸你的仓库**。
>
> 预计耗时：40–60 分钟，其中 30 分钟是下载引擎和第一次导入资源。

---

## 0. 先记住三件事（TL;DR）

| # | 事情 | 做错的后果 |
| --- | --- | --- |
| 1 | 他必须装 **团结引擎 1.10.4**（内部版本 `2022.3.62t16`），**不是 Unity** | 装 Unity 6 打开会触发升级、API 全红、美术全丢 |
| 2 | **先装 Git LFS，再 clone** | 所有 png/wav 变成 130 字节的指针文本，贴图全烂 |
| 3 | 打开后 **Console 零红字 + 能进大厅打一局** 才算成功 | 「能打开」≠「能跑」，红线不处理会一直烂下去 |

---

## 1. 你这边要做的（GitHub 上，5 分钟）

- [ ] **把他加成协作者**：仓库 → `Settings` → `Collaborators` → `Add people` → 输入他的 GitHub 用户名。
      不加也能 clone（公开仓库），但**不能 push**。
- [ ] **确认仓库是 Public**：`Settings` → 最下面 `Change visibility`。私有仓库老师/面试官打不开，等于没做。
- [ ] **确认 `main` 分支是最新且能跑的版本**：你本地先 `git status` 干净、`git push`，别让他拉到一个半成品提交。
- [ ] 把仓库地址发给他：`https://github.com/AwaKudsu/Roguelike2D-Tuanjie`

> ⚠️ 你本机的 remote 是 `ssh://git@ssh.github.com:443/...`，那是**你本机网络封了 22 端口**的特殊写法。
> **不要让他照抄**，他用标准 HTTPS 就行。

---

## 2. 他这边：装环境（顺序不要乱）

### 2.1 Git + Git LFS

1. 下载 Git for Windows：<https://git-scm.com/download/win>（一路 Next 默认即可）。
2. 打开 PowerShell，确认两个命令都有输出：

```powershell
git --version
git lfs version
```

3. 如果第二条报 `'lfs' is not a git command`，单独装：

```powershell
winget install GitHub.GitLFS
```

装完**关掉 PowerShell 重开**再验证（PATH 才会刷新）。

### 2.2 团结引擎 1.10.4（对应 `2022.3.62t16`）

1. 打开 <https://tuanjie.cn> → 下载 **团结 Hub**（Tuanjie Hub）。
2. 在 Hub 里安装编辑器，**版本必须选 `1.10.4`**，它对应的内部版本号就是 `2022.3.62t16`。
   - 工程根目录 `ProjectSettings/ProjectVersion.txt` 里写死了这个版本，装错会弹「版本不一致」。
   - 装**同一个小版本**就行，不要装 1.11 / 1.12：会触发资源重导入，还可能改 API，两个人的工程从此对不上。
3. 首次启动需要**登录团结账号**（个人版免费）。没有账号就在 Hub 里注册，别让他在这一步卡住。

### 2.3 磁盘与路径

- 工程放在 **纯英文、无空格** 的路径下，例如 `D:\Projects\Roguelike2D-Tuanjie`。
  中文路径 Unity/团结 一般能跑，但 Git、LFS、命令行工具链经常在这里出玄学问题。
- 预留 **10 GB 以上**空间：工程本体不大，但 `Library/` 首次导入会膨胀到 2–4 GB。

---

## 3. 拿代码（顺序是重点）

### 3.1 先启用 LFS，再 clone

```powershell
git lfs install          # 全局装一次，之后所有仓库都生效
```

### 3.2 克隆

```powershell
cd D:\Projects
git clone https://github.com/AwaKudsu/Roguelike2D-Tuanjie.git
cd Roguelike2D-Tuanjie
```

第一次 clone 会自动拉 LFS 素材，**几百 MB 属正常**，网慢就挂着。

拉完立刻验证 LFS 真的生效了：

```powershell
git lfs ls-files | Measure-Object -Line     # 应该几百行，不是 0
```

打开任意一张 `Assets/_Project/Art/Characters/Warrior/*.png`：

- **几十 KB 的图片** = 正常
- **130 字节、内容像 `version https://git-lfs.github.com/spec/v1`** = LFS 没生效，执行：

```powershell
git lfs install --local
git lfs pull
```

### 3.3 跑一次仓库自带的配置脚本

```powershell
powershell -ExecutionPolicy Bypass -File Tools\setup-git.ps1
```

它会做四件事：配 Git 基础项、注册场景合并驱动（SmartMerge）、启用 LFS、跑一遍忽略规则自检。
**看到自检全绿就行**，黄色警告按提示处理（通常是没找到 `UnityYAMLMerge.exe`）。

> 脚本是幂等的，跑第二遍不会出问题。

---

## 4. 第一次打开工程

1. 打开 **团结 Hub** → `Add` / `添加工程` → 选择 `D:\Projects\Roguelike2D-Tuanjie` 文件夹。
2. 用 `1.10.4`（`2022.3.62t16`）打开。
   - 如果弹「该工程由其他版本创建」，选**用当前版本继续**，**不要**点升级工程。
3. **耐心等**：首次导入要重建 `Library/`，3–10 分钟，进度条卡住是正常的，别强制关。
4. 导入结束后，打开场景：`Assets/_Project/Scenes/Game.unity`，按 `Play`。

---

## 5. 验收清单：什么算「完美运行」

让他逐条打勾，任何一条不满足就先别开始写代码：

- [ ] `Console` 里**没有红字**（黄色警告可以接受，红色不行）
- [ ] `Window → Package Manager` 里没有任何包显示 `error` / `missing`
- [ ] `Edit → Project Settings → Editor`：
      `Asset Serialization = Force Text`、`Version Control = Visible Meta Files`
      （这两项由工程文件锁定，正常情况下已经是这样；如果是别的值，说明他手动改过）
- [ ] 打开 `Game.unity` 后，Hierarchy 里没有 `Missing (Mono Script)` 的物体
- [ ] `Play` 之后：**进大厅 → 点角色 → 确认 → 走到门口按 E → 进关 → 能打怪**
- [ ] `git status` 里**只有** `Library/` 之类被忽略的东西，没有一堆 `Assets/` 下的改动
- [ ] 随便改一行注释，`git add` / `commit` / `push` 能成功（说明 SSH/HTTPS 凭据配好了）

全绿之后，让他**先跑一次完整的 `git pull` 再开工**。

---

## 6. 两个人协作的规矩（比技术配置更重要）

1. **开工前先 `git pull`，收工前先 `git push`。** 攒一天的改动再合并，必炸。
2. **不要两个人同时改同一个场景 / 预制体。** 改之前群里吼一声「我动 Game.unity 了」。
   SmartMerge 只能减少冲突，不能消除语义冲突。
3. **只提交这三类东西**：`Assets/`（含 `.meta`）、`ProjectSettings/`、`Packages/`。
   `Library/`、`Temp/`、`Logs/`、`UserSettings/`、`*.csproj`、`*.sln` 一律不进仓库。
4. **新增任何文件，一定要连 `.meta` 一起提交。** 漏一个 `.meta`，对方打开就是一片 `Missing Reference`。
   自检：`git status` 里看到 `Assets/.../Xxx.cs` 却没有 `Xxx.cs.meta`，说明漏了。
5. **用分支 + PR**：`feat/lobby-ui` 这种分支上干活，做完提 PR 让对方看一眼再合 `main`。
   直接往 `main` push 也可以（只有两个人），但别在 `main` 上做一半没编译过的提交。
6. **版本锁死**：谁都不许升级引擎。要升级必须两个人同时升级、同一天合完。

## 7. 报错对照表

| 现象 | 真正的原因 | 怎么修 |
| --- | --- | --- |
| 图片变成 130 字节文本 / 贴图全粉 | 没装 Git LFS 就 clone 了 | `git lfs install` → `git lfs pull` |
| `filter 'lfs' failed` | 同上，且 `.gitattributes` 里有 `filter=lfs` | 同上 |
| 打开工程弹 `Package [cn.tuanjie.ai.generators@file:...] cannot be found` | 拉到了**加入本指南之前**的旧提交（那个包指向作者本机的 `.codely-cli`，已从 `manifest.json` 移除） | `git pull` 到最新 `main` 即可 |
| `Failed to resolve packages` / 卡在 Resolving | 连不上 `packages.tuanjie.cn` 包服务器 | 检查网络/代理；关掉 VPN 试试；重启编辑器 |
| 场景里一堆 `Missing (Mono Script)` | `.meta` 没提交，或 LFS 没拉 | `git lfs pull`；`git status` 看有没有漏 `*.meta` |
| 打开是空场景 / 全白 | 没打开 `Assets/_Project/Scenes/Game.unity`，或场景文件被合并坏了 | 先确认场景路径；坏了就 `git checkout -- <场景文件>` 让作者重做 |
| 弹「版本不一致，是否升级」 | 装了别的编辑器版本 | 装回 `1.10.4` / `2022.3.62t16`；**不要**点升级 |
| `error: failed to push some refs` | 对方先 push 了，本地落后 | `git pull --rebase` 再 push |
| push 要密码 / 认证失败 | 没登录 GitHub 凭据 | 首次 push 会弹浏览器登录；或用 Personal Access Token |

## 8. 关于 Git LFS 的额度（提前说清楚，别到时候懵）

GitHub 免费账号的 LFS 额度是 **1 GB 存储 + 1 GB/月 下载流量**，两个人共用一个仓库就是共用这份额度。

- 现在工程里是几百张切好的 png，暂时够用。
- 一旦开始塞 **psd 源文件、音频、fbx 模型**，1 GB 很快见底。
- 超了之后 clone/pull 会报 `This repository is over its data quota`，**整个仓库对所有人拉不下来**。

对策（按优先级）：

1. **psd / 原始工程文件不要进仓库**，放在网盘，仓库只放导出的 png。
2. 图片压缩后再提交（切图用 png，别用无压缩 tga）。
3. 真超了就升级 GitHub 的 LFS 数据包，或把大素材挪到别的地方。
4. **千万别**为了省额度把 LFS 关掉、直接提交二进制——仓库会永久膨胀，改不回来。

## 9. 附：能不能直接打包文件夹发给他？

能，但**只作为应急**，而且必须排除这些目录，否则压缩包 10 GB 起步、还会带着你的本机缓存：

```
Library/  Temp/  Logs/  obj/  UserSettings/  .codely-cli/  _Tuanjie/install-*.json
```

只要他之后还想提交代码、还想跟你同步，**就必须走 Git**。压缩包只适合「我只是想看看效果」的场景。
