# 行动清单：从今天到交作业

> 项目：横板动作肉鸽（Dead Cells 类）　技术栈：团结引擎 2022.3.62t16（基于 Unity 2022.3）+ C#　工期：约 5 周（个人开发）
> 目标：①通过课程考核　②成为简历上一个能讲 20 分钟的项目

---

## 怎么用这份清单

| 标记 | 含义 | 说明 |
| --- | --- | --- |
| **P0** | 必须做 | 不做就没法交作业 / 游戏跑不起来 |
| **P1** | 应该做 | 决定作业是「及格」还是「优秀」 |
| **P2** | 加分项 | 决定它是「课程作业」还是「简历项目」 |

**两条铁律：**

1. **每完成一个勾选项，就提交一次 git commit。** 不要攒到最后一天一次性提交——那样你的 Git 历史毫无价值，老师一看就知道，简历上也不敢写。
2. **先做 P0，P0 全绿了再碰 P1。** 学生项目 90% 的死法是「第 2 周就想做联机 / 做 20 种武器 / 做剧情」，结果第 5 周连一局完整的游戏都跑不通。

## 阶段 0：地基（今天，1–2 小时）　P0

这一步做完，你后面 5 周才不会痛。

### 0.1 工程与版本管理

- [x] **P0** 确认团结引擎版本固定为 `2022.3.62t16`（Tuanjie Editor 1.10.4），**5 周内不要升级**（升级会触发资源重导入和 API 变更，纯浪费生命）
- [x] **P0** 团结工程位于 `D:\TuanjieRoguelike2D`（Unity 6 的原工程 `D:\Roguelike2D` 已冻结为只读参考，见 `docs/09-迁移到团结引擎.md`）
- [ ] **P0** 打开 `Edit → Project Settings → Editor`，设置：
  - `Asset Serialization` = **Force Text**　← 场景/预制体存成文本，Git 才能 diff 和合并，**这是 Unity + Git 最重要的一项设置**
  - `Version Control` = **Visible Meta Files**　← `.meta` 文件必须提交，否则资源引用全丢
  - `Line Endings For New Scripts` = **Unix**
- [ ] **P0** 确认 `.gitignore` 已忽略 `Library/`、`Temp/`、`Logs/`、`UserSettings/`、`Build/`、`*.csproj`、`*.sln`
  - 自检：`git status` 里**不应该**出现 `Library/` 下任何文件。如果出现了，说明 `.gitignore` 没生效
- [ ] **P0** 确认 `.gitattributes` 存在，且 `*.unity` / `*.prefab` / `*.asset` / `*.meta` 走 `merge=unityyamlmerge`
- [ ] **P0** 配置 Unity 的 SmartMerge 合并驱动（见 `03-Git使用手册.md`）
- [ ] **P0** 启用 Git LFS 并追踪图片/音频/模型（`.png .jpg .psd .wav .mp3 .ogg .fbx` 等）
  - **为什么必须现在做**：一旦某个大文件用普通 Git 提交过，想改成 LFS 就得重写历史。第一天做是零成本，第三周做是灾难
- [ ] **P0** 第一个 commit：`chore: 初始化 Unity 工程与版本管理配置`
- [ ] **P0** 在 GitHub 建**公开**仓库（简历项目必须公开，否则面试官看不到），push 上去
  - 仓库名：`D:\Roguelike2D` 同名，全小写加连字符也行（如 `roguelike-2d`）
  - **不要**勾选自动生成 README/.gitignore（你本地已经有了，会冲突）

### 0.2 项目结构

- [ ] **P0** 按 `Assets/_Project/` 组织自己的资源（结构见 `README.md`），第三方素材一律放 `Assets/ThirdParty/`
- [ ] **P0** `Assets/ThirdParty/` 下为每个素材包写一个 `SOURCE.md`，记录**名称 / 作者 / 链接 / 授权协议**
  - 这不是形式主义：老师会问「美术哪来的」，面试官也会问。能答出「CC0 / CC-BY，已标注」是专业素养

### 0.3 定名字

- [ ] **P1** 定一个英文项目名（仓库名、`.exe` 名、简历上都用它）。建议 2 个单词、好读好拼，例如 `Ashen Vault` / `Echo Rogue` / `Vaultbreaker`
- [ ] **P1** 写进 `README.md` 的标题和 `ProjectSettings` 的 `Product Name`
- [ ] **P2** 起个中文名做副标题（答辩时更亲切）

### 阶段 0 验收

> 你能打开工程、`git status` 干净、GitHub 上能看到你的工程文件但看不到 `Library/`。✅

## 阶段 1：垂直切片 —— 先让「一个房间」好玩（第 1 周）　P0

**本周唯一目标：一个方块小人，在一个房间里，能打死一个方块怪，能被方块怪打死，能重开。**
美术全是色块，**不要碰美术**。

### 1.1 输入与移动手感

- [ ] **P0** 安装并启用 **Input System**（新输入系统），定义 `Move / Jump / Dash / Attack` 四个 Action
- [ ] **P0** 角色移动：加速 / 减速（用 `Mathf.MoveTowards` 或速度插值，**不要直接赋值 velocity**，那样手感很硬）
- [ ] **P0** 跳跃手感四件套（这是动作游戏的命，**别跳过**）：
  - [ ] 土狼时间 Coyote Time：离开平台后 ~0.1s 内仍可跳
  - [ ] 跳跃缓冲 Jump Buffer：落地前 ~0.1s 按跳，落地自动起跳
  - [ ] 可变跳跃高度：松开跳跃键立刻削减上升速度
  - [ ] 下落重力 > 上升重力（通常 1.5–2 倍）
- [ ] **P0** 地面检测用 `Physics2D.OverlapCircle` + `LayerMask`，**不要**用 `OnCollisionEnter` 判断（会误判墙面）
- [ ] **P0** 冲刺（有冷却 / 有无敌帧）
- [ ] **P1** 二段跳

### 1.2 战斗

- [ ] **P0** 攻击判定：`OverlapBox` 在角色前方画一个矩形，命中后给对面上伤害
- [ ] **P0** 伤害传递统一走一个接口，别到处写 `GetComponent<Enemy>().hp -= 10`
  ```csharp
  public interface IDamageable { void TakeDamage(DamageInfo info); }
  ```
- [ ] **P0** 受击反馈三连：**闪白 + 击退 + 短暂无敌帧**（i-frames）
- [ ] **P0** 玩家血量 + 死亡 → 回到起点
- [ ] **P1** 三段连击（攻击窗口 + 连击计数 + 重置计时）
- [ ] **P1** 顿帧 Hitstop：命中瞬间 `Time.timeScale = 0` 约 0.05s。**性价比最高的手感提升**

### 1.3 敌人与摄像机

- [ ] **P0** 一个敌人，状态机三态：`Patrol → Chase → Attack`（用 `enum` + `switch` 手写即可，别上行为树）
- [ ] **P0** 敌人受击 / 死亡表现（变红、消失、掉东西）
- [ ] **P0** Cinemachine 摄像机跟随 + 边界限制 Confiner
- [ ] **P1** 摄像机前瞻 Lookahead（朝移动方向偏移一点）

### 阶段 1 验收

> 你把 `.exe` 发给室友，他能自己玩 30 秒不问你「怎么操作」。✅
> **这一步没做到，不许进入阶段 2。**

## 阶段 2：肉鸽骨架（第 2 周）　P0

**本周目标：一局游戏有「开始 → 打几个房间 → 变强 → 打 Boss → 死或通关」。**

### 2.1 关卡生成

- [x] **P0** 决定生成方案（二选一，**不要纠结**）：（已选 **A**，见 `docs/11-Day8房间池与种子.md`）
  - **A. 手工房间池 + 随机拼接**（推荐，Dead Cells 就是这个思路的变体）：做 8–12 个手工房间预制体，每间标好「入口/出口方向」，运行时按方向匹配拼接
  - **B. 网格程序生成**：用算法铺地块。**代码更炫但更慢出效果，且容易做出难看的关卡，不推荐课程作业**
- [x] **P0** 房间池用 `ScriptableObject` 管理，可配置权重、允许出现的最早关卡（`Assets/_Project/Data/Rooms/RoomPool_Default.asset`，字段 `weight` / `minRoomIndex` / `maxRoomIndex`）
- [x] **P0** 生成必须**可复现**：所有随机走一个 `System.Random` 实例，接受 `seed` 参数（`RoomManager.seed`，菜单 `团结 → 校验关卡随机` 会验证同种子同序列）
  ```csharp
  var rng = new System.Random(seed);   // ✅ 固定种子 → 固定关卡
  // UnityEngine.Random.Range(...)     // ❌ 全局状态，无法复现，无法写测试
  ```
  > 这一条同时是「P2 单元测试」和「答辩演示」的基础，**强烈建议照做**
- [ ] **P0** 摄像机在小房间之间切换（多房间同时渲染 / 单房间激活）

### 2.2 局内进度

- [ ] **P0** 关卡流程图：打完一个房间，出现 2–3 个门，通往不同类型房间（战斗 / 精英 / 商店 / 宝箱 / Boss）
- [ ] **P0** 房间类型：普通战斗 ×1、精英 ×1、商店 ×1、Boss ×1（**先各做一个就够**）
- [ ] **P0** 局内货币（灵魂/金币）+ 商店消费

### 2.3 掉落与词条（肉鸽的灵魂）

- [x] **P0** 用 `ScriptableObject` 定义词条数据，**不要在代码里写 if-else 堆词条**（`Assets/_Project/Scripts/Roguelike/RelicData.cs`）
  ```csharp
  [CreateAssetMenu(menuName = "Roguelike/Relic")]
  public class RelicData : ScriptableObject {
      public string displayName;
      [TextArea] public string description;
      public Sprite icon;
      public RelicEffect effect;      // 用多态：每个效果一个子类
      public Rarity rarity;
  }
  ```
  > 实际落地时用的是 `StatModifier[]` 而不是 `RelicEffect` 多态 —— 8 个词条全是数值修饰，够用；等要做「命中回血 / 击杀爆炸」这类**行为型**词条时再引入多态
- [ ] **P0** 至少 **8–10 个**词条，且**效果类型要分散**（加伤害 / 加攻速 / 位移强化 / 命中回血 / 击杀爆炸 / 击杀叠层）
  > 数量已到 8 个（`Assets/_Project/Data/Relics/`），但**效果全是数值修饰**，行为型的 4 类还没做。见 `docs/10-Day7词条与三选一.md` §9
- [x] **P0** 词条生效只需要改**一个属性集合**（例如 `PlayerStats`），玩家逻辑只读这个集合（`CharacterStats` + `StatModifier`，计算式 `flat * (1 + percentAdd) * percentMul`）
- [x] **P1** 三选一掉落界面（局内变强的主要爽点）（`RelicChoiceUI`，运行时用代码搭，数字键 1/2/3 或鼠标点选）

### 2.4 Boss 与敌人扩展

- [ ] **P0** Boss：2–3 个技能循环 + 两个阶段（血量 50% 时变招）
- [ ] **P1** 敌人总数到 4–5 种，行为要有明显区分（近战冲脸 / 远程放风筝 / 自爆 / 飞行）
- [ ] **P1** 精英怪 = 普通怪 + 一个词条改造（复用已有代码，性价比极高）

### 阶段 2 验收

> 你能连续玩 3 局，每局 5–10 分钟，并且**每局的体验不一样**。✅

## 阶段 3：构筑深度 + 局外成长（第 3 周）　P1

**本周目标：让「策略」二字成立——玩家的选择要有取舍，而不是无脑变强。**

- [ ] **P1** 武器系统：3–5 把，手感差异要**明显**（快剑 / 重锤 / 长枪 / 弓）
- [ ] **P1** 词条数量到 20+，并且做出**联动**：
  - 例：「暴击率 +15%」和「暴击时触发闪电」放在一起才有意义
  - 例：「攻速 +30%」和「每次命中叠 1 层流血」是乘算关系
  - > 有联动才叫构筑，没联动只是数字变大。**这是「策略」二字的全部含金量**
- [ ] **P1** 取舍设计：至少 3 处「二选一，且两个都想要」的决策点
- [ ] **P1** 局外成长（永久解锁）：用局内货币解锁新武器 / 新词条 / 基础属性上限
  - > 这是肉鸽「再来一局」的真正动力。**有它才叫肉鸽，没它只是个随机关卡游戏**
- [ ] **P1** 存档系统：JSON 存到 `Application.persistentDataPath`
  - 注意：**存档要带版本号字段**，方便以后改结构时做兼容
- [ ] **P1** 数值集中管理：把数值抽到 `ScriptableObject` 或 CSV，别散落在代码里 `hp = 100`
- [ ] **P2** 用 CSV / Excel 做数值表，写一个编辑器脚本一键导入成 `ScriptableObject`
  - 这个脚本本身就是很好的简历素材：「实现了数据驱动的数值管线，策划改表无需改代码」

### 阶段 3 验收

## 常见翻车点速查

| 症状 | 原因 | 处理 |
| --- | --- | --- |
| 仓库 2 GB，push 失败 | 素材没走 LFS / 提交了 `Library/` | 检查 `.gitignore`，回看 `.gitattributes` |
| 队友/自己合并后场景全白 | 没用 Force Text / 没用 SmartMerge | 见阶段 0.1 |
| 打开工程报一堆 `.meta` 缺失 | `.meta` 被 gitignore 了 | 必须提交 `.meta`，一个都不能少 |
| 打包版能跑但没声音/没画面 | 资源没被引用到，打包时被剔除 | 检查 `Assets` 引用链，或放进 `Resources`/Addressables |
| 越写越乱，改一个功能崩三个 | 系统间硬引用太多 | 引入 `IDamageable` 接口 + 事件解耦，别再往下加 |
