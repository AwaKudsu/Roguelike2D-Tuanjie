# Day 8：房间池、随机种子与房间类型

> 阶段 2「肉鸽骨架」的第一块：把「随机换房间」从代码里的一个 `List` 升级成**可配置、可复现、能分类型**的关卡流水线。
> 对应 `docs/00-行动清单.md` 的 2.1「关卡生成」。

---

## 1. 这一节改了什么

| 之前 | 现在 |
| --- | --- |
| 房间列表是 `RoomManager` 上的一个 `List<GameObject>` | 独立的资产 `RoomPool`，带权重和出现窗口 |
| 抽取用 `UnityEngine.Random`（全局状态，不可复现） | 全部走一个 `System.Random`，种子写在 `RoomManager` 上 |
| 房间没有类型概念 | 每个池子条目带 `RoomType`（战斗 / 精英 / 商店 / 宝箱 / Boss），由管理器注入给 `Room` |

## 2. 房间池：字段怎么配

`RoomPool_Default` 每一条有 5 个字段：

| 字段 | 含义 | 建议值 |
| --- | --- | --- |
| `prefab` | 房间预制体，必须带 `Room` 组件 | — |
| `type` | 房间类型 | 普通房 `Battle` |
| `weight` | 抽取权重，0 = 永不出现 | 普通 1、精英 0.35、商店 0.2 |
| `minRoomIndex` | 最早第几间房能出现 | 精英 5、商店 3 |
| `maxRoomIndex` | 最晚第几间（0 = 不限） | 一般填 0 |

几条规则：

- **同一个预制体可以登记多条**。比如同一间房在前期权重 1、后期权重 0.3，就写两条。
- **相邻两间不会重复**：抽的时候会排除上一次抽到的那条。池子里只剩一种可能时才允许重复（防卡死）。
- **池子只有 2 间时会变成严格交替**。这是「不重复」规则的自然结果，不是 bug —— 等房间做到 4 间以上才有意义。

## 3. 随机种子：为什么必须换掉 `UnityEngine.Random`

`UnityEngine.Random` 是**全局静态状态**：没有种子参数，同一个「局面」跑两次结果不同。

后果：

1. 出了 bug 没法复现 —— 「我这边房间顺序怪怪的」变成玄学；
2. 写不了单元测试 —— 「给定种子生成的关卡是否一致」这条根本没法测；
3. 以后加存档 / 每日挑战（同一个日期所有玩家同一套关卡）也无从谈起。

所以现在：

```csharp
// RoomManager.EnsureRandom()
_resolvedSeed = seed != 0 ? seed : (int)(DateTime.Now.Ticks & 0x7FFFFFFF);
_rng = new System.Random(_resolvedSeed);
Debug.Log($"[RoomManager] 本局种子 = {_resolvedSeed} ...");
```

- `Seed` 填 **0** = 每局随机，开局把实际种子打印到 Console；
- `Seed` 填**具体数字** = 固定关卡顺序。把 Console 里那个数字填回去，就能一模一样重新走一遍。

**怎么复现一局**：Console 里找到 `[RoomManager] 本局种子 = 1234567890` → 选中 `RoomManager` → 把 `Seed` 改成 `1234567890` → 重新 Play。

## 4. 房间类型：类型由「谁创建它」决定

`RoomType` 有 5 个值：`Battle / Elite / Shop / Treasure / Boss`。

关键设计：**房间不自己声明类型**，而是由 `RoomManager` 在实例化之后注入：

```csharp
// RoomManager.BuildRoom()
var entry = roomPool.Entries[index];
_currentRoom.Initialize(this, entry.type);   // ← 类型是外部配置，不是预制体属性
```

好处是同一个预制体今天当普通房、明天当精英房，只改池子配置，不用复制预制体。房间只做一件事：数敌人死光没有、死光了开门。

## 5. 一键装配与校验

菜单都在顶部 **团结** 下。

### 5.1 `团结 → 生成房间池`

做的事：打开 `Game.unity` → 扫描 `Assets/_Project/Prefabs/Rooms/` 下所有预制体 → 没有池子就新建 → 池子为空就按「全部战斗、权重 1」写入 → 逐条体检（有没有 `Room` 组件）→ 接进 `RoomManager` → 存盘 → 写报告 `_Tuanjie/day8-report.txt`。

**池子已经有内容时不会覆盖** —— 那是你手调的权重，跑一次脚本就没了会很糟。

### 5.2 `团结 → 校验关卡随机`

纯逻辑校验，不开场景、不依赖帧率，几十毫秒跑完：

- 同一个种子跑两遍，序列必须完全一致；
- 换一个种子应该得到不同序列；
- 连抽 20 间，相邻两间不能是同一间。

报告写到 `_Tuanjie/day8-seed-report.txt`。实测结果（池子 2 条时）：

```
[PASS] 同种子 → 同序列
        种子 20261021：Room_02 → Room_01 → Room_02 → ... （交替，因为池子只有 2 间）
[PASS] 相邻两间不重复 | 连抽 20 间
[INFO] 池子条目 | 2 条
```

## 6. 验收步骤

1. 按 `Play`，Console 里应该出现两行：
   ```
   [RoomManager] 本局种子 = <数字>（想复现这一局，把它填进 Seed 字段；填 0 表示每局随机）
   [Room] Room_01（战斗）：敌人 2 个，门锁着
   [RoomManager] 进入第 1 间：战斗「Room_01」
   ```
2. 打完一间进下一间，Console 继续打印「进入第 2 间：战斗「Room_02」」。
3. 把 `Seed` 填成 Console 里那个数字，重新 Play —— 第 2、3 间的顺序应该和上次完全一样。
4. （可选）在 Inspector 里选中 `RoomPool_Default`，把 `Room_02` 的 `weight` 改成 3 再 Play，第二次出现的次数会明显变多。

## 7. 排错表

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| Console 报「房间池是空的，一间都生不出来」 | `Room Pool` 没接，旧列表也空 | 跑 `团结 → 生成房间池` |
| 每局顺序都一样 | `Seed` 被填成了固定值 | 把 `Seed` 改回 `0` |
| 一直只出现同一间 | 池子里只有 1 条，或其余条目的 `weight = 0` | 检查权重与 `minRoomIndex` |
| 第 1 间就出了精英 / Boss | 那条的 `minRoomIndex` 是 1 | 把 `minRoomIndex` 调大 |
| Console 报「第 N 间抽不到任何房间」 | 所有条目的出现窗口都不覆盖这一间 | 检查 `min/maxRoomIndex` |

## 8. 已知限制 / 下一步

- **只有一种房间类型是真的**：`Elite / Shop / Treasure / Boss` 枚举已经在，但还没有对应的房间预制体和内容。
- **没有「打完出 2~3 个门让你选」**：现在还是一扇门直通下一间。这是阶段 2.2 的核心，下一步就做它 —— 类型已经就绪，门只需要按类型从池子里抽 3 个候选给你挑。
- **还没有 Boss**：阶段 2.4。
- **词条仍然是 8 个，效果全是数值修饰**：清单要求的「命中回血 / 击杀爆炸 / 击杀叠层」这类效果型词条还没做（需要 `RelicEffect` 多态，现在的 `StatModifier[]` 表达不了）。
