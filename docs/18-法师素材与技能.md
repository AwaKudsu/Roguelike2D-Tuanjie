## 2. 素材：一张姿势表怎么变成 21 张帧

### 2.1 抠图判据

原图 `1254×1254`、RGB 无透明通道、背景是**带噪声的深绿**。去背用的是颜色关系而不是固定色：

```python
green = (g - max(r, b) > 5) & (g > 28)     # 「绿得明显」才当背景
mask  = ~green
```

法师身上有紫袍、金饰、棕木杖，`g` 都不会明显高于 `r/g` 两者，所以不会被误判。覆盖率 0.2788（约 28% 是角色）。

### 2.2 画布与锚点（和战士同一套规矩）

| 参数 | 值 | 为什么 |
| --- | --- | --- |
| 画布 | 320×480 | 最宽的一帧（前推 + 杖）约 220px，320 够；高 480 留出法术特效空间 |
| PPU | 160 | 角色约 160px 高 → **1 单位 ≈ 一个身高**，和战士一致，手感不变 |
| 脚底 | 距画布底 160px | `(160-240)/160 = -0.5`，脚底正好落在胶囊体底边 |
| 水平锚点 | 底部 18 行不透明像素的 x 均值 | 换帧不左右跳 |

`foot_line()` 取的是「底部中央 50% 宽度里、连续 ≥8 个不透明像素的最低行」，不是整帧最低行 —— 法师的**法杖杖尖比脚更低**，取最低行会把整个人顶起来，走起来像飘。

### 2.3 21 张帧的来路

| 来源 | 产出 |
| --- | --- |
| 正视图 ×1 | `Mage_Idle` + `Mage_Idle_2`（上抬 2px）+ `Mage_Idle_3`（上抬 3px、纵向 0.995） |
| 行走 4 帧 | `Mage_Run_0..3` |
| 行走帧压缩 | `Mage_Run_4`（Run_0 ×0.97）、`Mage_Run_5`（Run_2 ×0.97）＝落地缓冲 |
| 攻击 4 帧 | `Mage_Attack_0..3`（举杖 / 蓄力发光 / 前推 / 收招） |
| 施法 3 帧 | `Mage_Cast_0..2`（举杖 / 头顶光环 / 收尾） |
| 派生 | `Mage_Jump`（Attack_1 上抬 6px）、`Mage_Hurt`（Cast_0 +1px、×0.97）、`Mage_Death`（Idle 压到 0.42 高） |
| 素材原样 | `Mage_Ring`（法阵）、`Mage_Fireball`（火球） |

派生帧只做**平移 + 绕脚底纵向压缩**，不做旋转 —— 像素画旋转要重采样，边缘会糊。

### 2.4 法阵被挖掉了一半（踩坑记录）

第一版按「法师的包围盒」把人物从法阵里挖掉，结果**圆的下半圈一起没了**：法师站在圆的中间偏下，他的盒子覆盖了圆的下半。

第二版改成按连通块判断：在法阵 crop 里做连通块标记，**只丢「完整落在法师包围盒内」的块**，保留所有探出法师范围的像素 → 拿到上半圈 + 两侧。

第三版 `ring_complete.py` 把上半部分**垂直镜像**拼到下半（`FLIP_TOP_BOTTOM` + `alpha_composite`），得到完整圆环（顶部与底部各留一条横杠，正好对称）。最终 `Mage_Ring.png` 186×186。

## 3. 技能层怎么做到「不认职业」

法师和战士是两套动画组件，但 `SkillCaster` 不该知道玩家现在是谁。所以抽了一个接口：

```csharp
public interface IPlayerAnim
{
    void PlaySpin(float duration);   // 旋风斩：持续型攻击姿态
    void PlayWarcry(float hold);     // 战吼：举起来吼一声
    void PlayCharge(bool on);        // 蓄力中（战士空实现）
    void PlayCast(float hold);       // 施法（法师举杖）
}
```

`WarriorVisual` 与 `MageVisual` 都实现它；`SkillCaster` 用 `ResolveAnim()` 找**当前 enabled 的那个**（两个组件同时存在，只有一个开着）。

**为什么要「找 enabled 的」**：`GetComponent<IPlayerAnim>()` 会返回第一个匹配的组件，哪怕是 disabled 的 —— 换职业后就会播到已经关掉的那套动画上。

## 4. 蓄力火球

### 4.1 时序

```
按下 K
  └─ IsChargeable? 是 → 进入蓄力（此时不扣蓝、不进冷却）
       ├─ 每帧 _chargeTimer += dt（封顶 chargeTime）
       ├─ 法师停在「杖头发光」那一帧
       └─ 松手 / 被打断 / 技能被禁 → ReleaseCharge()
            ├─ 这一刻才扣蓝、才进冷却（TryPayCost）
            └─ CastProjectile(skill, ratio)
```

**为什么扣蓝放在松手时**：蓄力被打断（挨打、切场景、蓝被其他技能花掉）不该白扣一次蓝。

### 4.1b 蓄力时看得见的那颗球（2026-11-05 补）

第一版只有「法师停在举杖那一帧」，玩家按住 K 时画面上几乎没变化 —— 于是被当成「火球不能蓄力」。现在 `MageVisual` 在蓄力期间会在杖头生出一颗 `Mage_Fireball`：

- 位置 `chargeOrbOffset = (0.62, 0.34)`，按 `sprite.flipX` 左右镜像；
- 大小 `Lerp(chargeOrbMinScale = 0.55, chargeOrbMaxScale = 1.85, ChargeRatio)` —— 蓄满时直径约 1.1 个世界单位，比法师本人还大；
- 蓄满后叠一层 `1 + 0.06 sin(18t)` 的脉动，提示「再蓄也不会更大了」；
- 透明度 `Lerp(0.55, 1, ratio)`，球是 `sortingOrder 22`，压在人物（20）上面。

**体积还有一半在技能资产上**：`Skill_Fireball.chargeMaxScale = 3.2`（松手后飞出去那颗的尺寸 = 预制体基础缩放 0.45 × 3.2）。
两处要一起调，只改一边会出现「杖头很大、飞出去很小」或者反过来。2026-11-05 按「体积再大一些」的反馈，球从 1.25 → 1.85、投射物从 2.2 → 3.2。

**这两个数字必须写进场景**：`MageVisual` 挂在场景里的 Player 上，字段值早就序列化过了，改 C# 里的默认值不会生效 —— 要让 `MageArtBuilder` 用 `SerializedObject` 把 `chargeOrbMinScale / chargeOrbMaxScale / chargeOrbOffset` 一起写进去，然后重跑「团结 → 导入法师素材」。

另外 `SkillCaster` 在开始蓄力和发射时各打一行 `Debug.Log`（`[SkillCaster] 火球术 开始蓄力 / 蓄力 100% 发射`）—— 这两行是给「到底是没进蓄力、还是进了没显示」用的，排查完可以删。

### 4.1c 修过的 bug：有时候蓄不了力（2026-11-05）

**现象**：法师大部分时候能蓄力，偶尔按下去直接飞出一颗小球（= 0% 蓄力）。

**根因**：`PlayerInputReader` 的「松手」是一枚**锁存**（`_skillReleasedLatch[slot]`），只有 `UpdateCharge()` 在真正蓄力时才会消费它。而这两种情况下松手没人消费：

- 按在冷却 / 蓝不够里 —— `BeginOrCast` 直接 return，根本没进蓄力；
- 蓄力被硬直打断 —— `CancelCharge()` 清掉了 `_chargeSlot`，之后松手落到空处。

于是锁存一直挂着。**下一次**按下时先 `BeginOrCast` 进蓄力、下一帧 `UpdateCharge` 一看「已松手」就立刻以 0% 发射 —— 表现正是「有时候蓄不了力」。

**修法**：进入蓄力的那一刻清掉旧锁存：

```csharp
_chargeSlot = slot;
_chargeTimer = 0f;
input.ConsumeSkillReleased(slot);   // ★ 清掉上一轮遗留的「已松手」
```

删掉这行时回归用例必然会红（实测：`[FAIL] 旧松手锁存把蓄力顶掉了 | 按下=True 第二帧仍在蓄=False`），加回来才绿 —— 用例不是摆设。

**顺带**：放不出来时在头顶飘一行黄字（`SkillCaster.Hint()`）：「火球术 冷却中 1.2s」「法力不足（需要 12）」。以前这些只写进 Console，还被 `logFailures` 关着，玩家只会觉得「按了没反应」。

### 4.2 三个倍率

| 参数 | 值 | 含义 |
| --- | --- | --- |
| `chargeTime` | 1.1 s | 蓄满要多久 |
| `chargeMinScale` | 1.0 | 刚按下时球的倍率（**以前这里写 0.7 但代码没用它**，短蓄力一直是 1 倍基础大小） |
| `chargeMaxScale` | 2.6 | 蓄满时球的倍率 |
| `chargeMaxSpeedBonus` | 1.9 | 蓄满时速度倍率 |
| `chargeMaxDamageBonus` | 2.0 | 蓄满时伤害倍率 |

投射物这边：`Projectile.Launch(..., sizeScale, speedScale)` 会 `transform.localScale *= sizeScale` —— **`CircleCollider2D` 跟着变大**，所以「看着打中了」就是真打中了。同时 `_lifeTimer = lifeTime / speedScale`，飞得快则存活时间同比缩短，**射程不变**。

伤害在 `ProjectileLauncher.Fire(..., damageMultiplier, ...)` 里乘在发射瞬间算好的 `DamageInfo` 上，飞行途中不再变。

### 4.3 修过的 bug：蓄满力反而打不出伤害（2026-11-06）

**现象**：轻点一下（短蓄力）火球正常飞出去、正常扣血；按住蓄满再松手，火球当场消失、一点伤害都没有。

**根因有两层，都跟「球变大」有关**：

1. **出生点没有高度**。`MuzzlePosition` 原来是 `owner.position + (0.55 * facing, 0)` —— 球是从**腰高**生成的。蓄满时 `sizeScale = 2.6`，`CircleCollider2D` 半径跟着乘上去，世界半径到 0.76；而玩家落地后球心只比地面高 0.5 → 球的下缘直接埋进 `Ground`（第 8 层，预制体 `obstacleLayers = 256`）→ `OnTriggerEnter2D` 判定成撞墙 → `Expire()`。
   **蓄得越大，越必然一出生就撞地板** —— 这就是「轻点没事、蓄满必哑火」。
2. **碰撞体跟着贴图无限放大**。就算出生点抬高了，半径涨到超过球心离地高度，整颗球飞行全程都会蹭着地板，边蹭边 `Expire`。

**修法（三处，缺一不可）**：

| 改动 | 文件 | 说明 |
| --- | --- | --- |
| 出生点随体积抬高 | `ProjectileLauncher.MuzzlePosition(owner, facing, sizeScale)` | `forward = 0.55 + (sizeScale-1)*0.45`、`up = 0.12 + (sizeScale-1)*0.22`；满蓄从 (0.55, 0) 变 (1.21, 0.47) |
| 碰撞体封顶 | `Projectile.maxColliderScale = 1.6f` | 贴图吃满 `sizeScale`，`CircleCollider2D.radius` 补偿成 `base * 1.6 / sizeScale`，世界半径最多 1.6 倍（0.76），不再随蓄力无限长 |
| 出生宽限 | `Projectile.obstacleGrace = 0.08f` | 出生 0.08 秒内不吃「撞墙」判定，兜住「刚好压在墙里生成」这类边角 |

**顺带把短蓄力也改大了**：`sizeScale` 改成 `Mathf.Lerp(chargeMinScale, chargeMaxScale, t)`（以前是从 1 开始插值，`chargeMinScale` 根本没被读），`Fireball.prefab` 的 `m_LocalScale` 从 0.45 提到 **0.95**，蓄力球（杖头那颗）也从 0.55→1.85 提到 **0.8→2.2**。效果：轻点一下的球从 0.45 单位变成 0.95 单位，蓄满从 1.44 变成 2.47。

**自检新增（`MageCheck.CheckProjectileGrowth`）**：

```
[PASS] 枪口高度 | 1 倍时抬高 0.12，满蓄抬高 0.47（球越大出生点越高）
[PASS] 碰撞体封顶 | 贴图放大 2.47 倍，判定半径 0.76（基础 0.48，最多 1.6 倍）
[PASS] 火球出厂大小 | 基础 0.95 倍 × 满蓄 2.6 = 2.47（短蓄力也不小）
```

这三条都是**之前能过、但问题仍在**的那类断言的反面：只断言「Launch 能被调用」抓不住「一出生就撞地板」，必须断言几何关系（抬高量、世界半径上限）。

## 5. 回复：法阵 + 分段回血 + 绿字

### 5.1 三段表现

| 时间 | 发生什么 |
| --- | --- |
| 0.0 s | 法师举杖（`Mage_Cast` 3 帧序列），法阵从 0.45 单位张开到 3.2 单位 |
| 0.0～2.4 s | 每 0.3 秒回一次血（共 8 次，每次 6 点 = 48 点），每次头顶飘一条 `+6` |
| 2.4～2.55 s | 法阵淡出销毁 |

### 5.2 三个实现细节

**① 法阵是椭圆，不是圆** —— `localScale = (size, size * 0.55, 1)`。完全平放的圆环悬浮在胸前会像贴在屏幕上的贴纸；压扁到 55% 才像躺在地上的法阵。

**② 回血是「流」不是「一口」** —— `Health.Heal(6)` 每 0.3 秒跳一次。一次回满就没有「正在恢复」的过程，玩家也不会注意到法阵还在持续。

**③ 满血不刷屏** —— `Heal()` 返回实际回了多少，`<= 0.01` 就不飘字。

### 5.3 飘字为什么不用 TextMesh

`TextMesh` 用旧版字体材质，中文字形要**预烘进图集**，运行时加载不到就全是方块。所以 `FloatingText` 走 `UI.Text` + `Font.CreateDynamicFontFromOSFont`（和菜单、词条面板同一套办法），代价是每帧要把世界坐标换算成屏幕坐标：

```csharp
_rect.position = Camera.main.WorldToScreenPoint(_anchor + Vector3.up * lift);
```

飘字用 `Time.unscaledDeltaTime` —— 暂停菜单打开时飘字不该冻在半空。

## 8. 排错

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 切到法师后还是战士的样子 | `PlayerVisualSwitcher` 没挂，或者职业表空 | 跑一次「导入法师素材」，或手动填 `classes` |
| 法师站着不动/贴图不换 | 两套动画都没 enabled | 切换器 Awake 会先全关，Start 再开一个；若手动禁用过就重新勾上 |
| 按 K 不放，火球没变大 | `Skill_Fireball.chargeable` 没勾 | 勾上，或跑一次导入菜单 |
| 蓄力时挨打，球没发出去 | 设计如此（打断不发射） | 想改成「打断也发射」在 `CancelCharge` 里调 `ReleaseCharge` |
| 回血没有绿字 | `FloatingText` 的 Canvas 没建出来（字体失败） | 看 Console 有没有「系统字体没找到」，那是 `LegacyRuntime.ttf` 兜底，中文会变方块 |
| 法阵是个饼 | y 没压扁 | `HealCircle` 里 `size * 0.55` 那行别改回 1 |
| 蓄力球看着打中人却没伤害 | 只缩了贴图没缩碰撞体 | 必须 `transform.localScale *= sizeScale`（整物体缩），不能只改 `sprite` 尺寸 |
| **有时候**按 K 蓄不了力（有时好好的） | 松手事件留了个「旧锁存」没被消费：按在冷却里、或蓄力被硬直打断后松手，都会留下它；下一次按下时 `UpdateCharge` 立刻判成「已松手」，以 0% 甩出去 | 已在 `BeginOrCast` 里进入蓄力时先 `input.ConsumeSkillReleased(slot)` 清掉；回归用例见 §7「旧松手锁存不影响下一次蓄力」 |
| 按住没反应、头上飘「冷却中 / 法力不足」 | 不是 bug：冷却 1.5 s、耗蓝 12，被挡住了 | 等冷却或回蓝；提示文字在 `SkillCaster.Hint()`，想换颜色改那里 |
| 火球往左飞时看着「倒着飞」 | 素材里的火球是**朝右**画的（球在右、拖尾在左），飞行方向变了但贴图没翻 | `Projectile.mirrorToDirection`（默认开）会在 `Launch` 里按 `direction.x < 0` 设 `flipX`；新做带方向的投射物照这个来 |
| 蓄力时杖头那颗球是反的 | 蓄力球和投射物共用同一张火球图，但它是 `MageVisual` 自己挂的子物体，**不吃 `Projectile` 的翻转** | `MageVisual.UpdateChargeOrb()` 里 `_chargeOrb.flipX = dir < 0f`；`MageCheck` 有两条断言（朝右不翻 / 朝左翻） |
| 轻点能打、**蓄满打出去就没了** | 球大了但出生点在腰高、碰撞体也无限放大 → 一出生就压在 `Ground` 上，被判成撞墙当场 `Expire` | 见 §4.3：`MuzzlePosition` 随体积抬高 + `Projectile.maxColliderScale` 封顶 1.6 + `obstacleGrace` 0.08 s |

## 9. 已知限制

1. 法师没有独立的冲刺帧、胜利帧（冲刺用跑动帧顶，胜利没接）。
2. 蓄力进度只影响大小/速度/伤害，不影响弹道形状（还是直线）。
3. `PlayerVisualSwitcher` 用职业名字里是否含「法」判断表现层，加第三个职业时要改成查表。
4. 回血不吃治疗加成（没有这个词条），固定每次 6 点。
5. 法阵只跟着角色走，不会随地形倾斜；地面上有高低差时会有一点点穿模。
6. 蓄满的火球判定半径封顶在 1.6 倍（0.76 单位），比贴图略小 —— 贴图可以更大，判定不跟着无限长，否则整颗球都在蹭地板。
