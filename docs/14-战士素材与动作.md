# Day 10 · 战士素材与动作

> 目标：把一张「骑士姿势总表」切成能用的动画帧，接进玩家身上，让战士的待机、跑、跳、冲刺、三种攻击、受击、死亡、胜利都有姿势，并且挥砍时飞出刀风。

---

## 1. 素材的情况：它不是图集，是一张姿势表

拿到的是 **1254×1254、RGB、没有透明通道** 的一张图，背景是一片带噪点的深绿。也就是说：

- 不能直接当精灵用（背景会一起画出来）；
- 也不是规整的「每帧 64×64、按行排列」的图集 —— 每个姿势的尺寸、间距都不一样。

所以第一步不是写代码，而是**抠图和切块**：

| 步骤 | 做法 | 结果 |
| --- | --- | --- |
| 抠背景 | 判据 `g - max(r,b) > 5 且 g > 30` 视为绿色背景，其余保留 | 前景覆盖 28.4% |
| 连通块标记 | 自己写的两趟 union-find（不引第三方库） | 67 个块 |
| 过滤 | 只留 ≥150 像素的块 | 22 块 |
| 人工判读 | 逐块看 bbox 与内容 | 有 3 张是展示大图、2 条速度线、2 颗闪光、1 道刀风，**真正的人物帧只有 13 张** |

抠图判据为什么成立：骑士的黑色描边 `g - b ≈ -2`，不会被当成绿色；深绿的噪点差值都在 5 以上。

> 中间脚本放在 `D:\tjart\`（纯 ASCII 路径）。**不要在中文路径上跑 Python 脚本** —— 用 PowerShell 写 `.py` 会把「2D肉鸽」写成 `2D??`，直接 `OSError: [Errno 22]`。

## 2. 为什么画布是 320×480、PPU 是 160

这一步最容易做错，也最影响手感，先把理由写清楚。

**约束**：`SpriteRenderer` 必须留在 Player 根物体上，不能塞进子物体 —— `HitReaction.cs` 用 `GetComponentInChildren<SpriteRenderer>()` 找渲染器做受击闪白，一旦有子渲染器，闪白会打到错的渲染器上。

**于是脚底只能靠精灵自己的 pivot 对齐**，而胶囊体是 1×1、中心在原点，底边在 `y = -0.5`。

| 参数 | 取值 | 为什么 |
| --- | --- | --- |
| 画布 | 320×480 | 最宽的姿势是突刺（211px 宽的剑），256 宽放不下 |
| PPU | 160 | 骑士本体 161px → **正好 1 单位高**，和原来的方块占位一样高，不动手感 |
| pivot | 居中 (160, 240) | 画布 3 单位高，脚底固定在距画布底 160px → `(160−240)/160 = −0.5`，正好落在胶囊体底边 |
| 水平对齐 | 脚底 18 行像素的质心对齐画布中心 | 否则每换一帧人物会左右抖一下 |

抠图后每帧单独贴到 320×480 的透明画布上，脚底统一压在「距底 160px」，所以换帧时人是站住的。

## 4. 顺带补的：冲刺原本是空的

查代码时发现一件不太好的事：`PlayerInputReader.ConsumeDashPressed()` **全工程没有任何调用者** —— 也就是说 README 上写着 `LeftShift` 冲刺，实际上按下去什么都不会发生。之前以为「冲刺无敌帧」已经做了，实际那只是受击后的无敌帧。

所以这次把它补上（也就 40 行）：

| 参数 | 值 | 效果 |
| --- | --- | --- |
| `dashSpeed` | 18 | 跑速默认 8，窜出去明显更快 |
| `dashDuration` | 0.18s | 短促，不是滑行 |
| `dashCooldown` | 0.55s | 不能连按刷位移 |
| `dashInvincibility` | 0.18s | 冲刺全程无敌，可以穿弹幕 |

实现上有三处讲究：

1. **冲刺期间关重力**（`gravityScale = 0`）并直接接管速度，否则短促的一次冲刺会被重力压成一个斜下坠；
2. **没方向输入时顺着最近朝向走**（`_lastFacing`），站着按冲刺也应该是「往前窜」，不是原地抖；
3. **挨打会打断冲刺**（硬直分支里 `_dashTimer = 0`），否则被打的同时还能无敌位移。

## 5. 状态机优先级

`WarriorVisual.ChooseFrame()` 从上往下挑，先命中的赢：

```
死亡 > 受击 > 冲刺 > 攻击 > 空中(起跳/下落) > 跑动 > 待机
```

几个刻意的决定：

- **冲刺压在攻击之上** —— 窜出去的瞬间不该还被挥砍姿势钉着；
- **攻击是「事件 + 计时」而不是「播完一段动画」** —— `PlayerAttacker` 只在真正出手时抛一次 `AttackStarted`，`WarriorVisual` 收到后按攻击类型选姿势、压 `attackHold`（普攻 0.15s / 横扫 0.26s）。攻击判定和表现完全解耦：删掉这个事件，战斗照常工作；
- ~~**胜利姿势靠轮询房间状态**~~ —— **2026-11-05 按用户要求删掉了**（连同 `victory` 字段、`victoryHold`、`CheckRoomCleared()`；`PlayWarcry` 的兜底姿势从 `victory` 换成 `attackHeavy`）。删的理由：清房那一刻举剑 1.4 秒会盖掉紧接着的跑动/攻击，读起来像卡了一下；`WarriorCheck` 现在反过来断言「`victory` 字段不存在」；
- **跑动帧按 `floor(t × 10fps) % 4` 取** —— 素材里 4 张跑动帧本身不构成严格循环（有两张偏正面），所以不追求完美循环，只求「跑起来不是一张静止图」。

## 6. 挥砍弧光：贴着武器扫（原「飞行刀风」已作废）

> **2026-11-05 改版**：这一节原来写的是「弧光脱手往前飞」。实际跑起来那个读感更像法师的气刃，不像战士挥剑，已经换成**贴着武器绕角色扫过**的残影（`SlashTrail.cs`），飞行刀风 `SlashWave.cs` 已删。实现与新参数见 [docs/15-战斗表现与战吼.md](15-战斗表现与战吼.md) 第 2 节。

留下两条仍然成立的坑：

- **弧光是斜的**：原图是「左上粗、右下勾」的一弯新月，左右两侧要镜像（`flipX`）才不会一边顺手一边别扭；
- **画布不能留白**：那张图原本在 320×480 的画布里偏左上。现在绕「角色」旋转，画布留白同样会把弧光甩得到处都是，所以仍紧贴弧光裁成 **189×189 的正方形**（PPU 仍是 160 → 约 1.18 单位），pivot 落在弧光中心。

大范围横扫（判定框面积 ≥ 6，比如旋风斩 3.2×2.2 = 7.04）走 `SlashEffect.Spin(...)`：绕身转 720°、0.42 秒，用的是原地张开的 `SlashArcFade`。

弧光颜色在 `PlayerAttacker.slashColor`（默认暖白 `(1, 0.94, 0.75)`），嫌太淡可以直接改。

## 7. 三段连击

普通攻击现在是三连：**劈砍 → 上挑 → 突刺**，每段有独立的 `AttackData`。

| 段 | 资产 | 判定框 | 偏移 | 够得着 | 倍率 | 击退 | 冷却 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 劈砍 | `Attack_Combo1.asset` | 1.9×1.1 | 1.00 / 0.05 | 1.95 | ×1.0 | 6 | 0.16 |
| 2 上挑 | `Attack_Combo2.asset` | 1.6×1.8 | 0.95 / 0.35 | 1.75 | ×1.25 | 4 | 0.18 |
| 3 突刺 | `Attack_Combo3.asset` | 2.8×1.0 | 1.45 / 0.00 | 2.85 | ×1.7 | 10 | 0.34 |

判定框形状是刻意这么配的：**劈砍又宽又平**（扫地）、**上挑又高又窄**（打浮空）、**突刺又长又薄**（够得着对面）。

「够得着」= `|offset.x| + size.x / 2`，单位是一个角色身高（骑士本体就是 1.0 单位）。判定框是按**中心点**算的，所以宽度里有一半在身后；劈砍 1.95 意味着从身体中线往前能摸到接近两个身位。

> 2026-11-05：三段整体加长了约 25%（原来是 1.55 / 1.40 / 2.30），因为 1.55 只比敌人的爪子长一点点，追着敌人砍时老是差半格。
> 弧光的位置**不写死**，`PlayerAttacker.PlaySlash` 用同一份 `AttackData` 反推 `reach`，所以以后只改判定框，扫光自动跟着变长。

判定框形状是刻意这么配的：**劈砍又宽又平**（扫地）、**上挑又高又窄**（打浮空）、**突刺又长又薄**（够得着对面）。

连击窗口 `PlayerAttacker.comboWindow = 0.55` 秒：

- 上一段打完 0.55 秒内再按 → 接下一段；
- 超时（或第一次按）→ 从第一段重来；
- 三段打完再按 → 循环回第一段。

姿势也分三段：`WarriorVisual.attackSlash` / `attackLift` / `attackThrust`，靠 `PlayerAttacker.ComboStage`（0/1/2）选。**事件签名没改**（仍是 `Action<AttackData>`），因为段号本来就存在攻击者身上，外观层直接读就行 —— 少改一个接口就少一处会漏的地方。

### 为什么之前「攻击模组是法师的」

不是场景接错，是**有一段配置从来没被读过**：

```
Class_Warrior.basicAttack = Attack_Combo1（近战，第一段劈砍）
Class_Mage.basicAttack    = Attack_MageBolt（远程弹道）
```

`ClassData.basicAttack` 这个字段从 Day 3 加上去以后，**全工程没有任何代码读它**。玩家的职业数据一直是 `Class_Warrior`（所以血 140、攻 13 都是战士的），但 `PlayerAttacker.attackData` 是 Day 5 在 Inspector 里手填的 `Attack_MageBolt`。于是：**满身板甲、拿剑挥，飞出去的是法师的魔弹。**

修法是让攻击跟着职业走（`PlayerAttacker.ApplyClassAttack`）：

- `Start()` 里取 `CharacterStats.Class.basicAttack` 装上（放 `Start` 不放 `Awake`：`CharacterStats` 是在它自己的 `Awake` 里才应用职业数据的，两个 `Awake` 谁先跑没保证）；
- 订阅 `CharacterStats.ClassChanged`，以后换职业自动换武器；
- 武器仍然优先：`Equipment` 穿了带 `weaponAttack` 的武器就覆盖，脱下时还原**职业的那一个**。

顺带修了 `Equipment` 的一个隐患：它原来在 `Awake` 里就把「出厂攻击」记成 `attacker.CurrentAttack` —— 那时职业还没应用，记下来的是场景里的旧值，脱下武器会把魔弹还回去。现在改成**第一次真正需要时再取**（`DefaultAttack()`），那时职业早就装好了。

## 9. 排错表

| 现象 | 原因 | 怎么修 |
| --- | --- | --- |
| 人物变成一张白方块 | 贴图导入成了 `Default` 而不是 `Sprite` | 重跑「导入战士素材」，或手动把 Texture Type 改成 Sprite |
| 人是糊的 | 过滤模式不是 Point，或被压缩了 | 检查 Filter Mode = Point、Compression = None |
| 脚陷进地板 / 浮在半空 | PPU 或 pivot 不对 | 跑自检，看「脚底对齐」那条 |
| 换帧时人左右抖 | 画布没按脚底质心对齐 | 重新切图（`slice.py`） |
| 挥砍没有刀风 | `PlayerAttacker.slashArc` 没接 | 重跑「导入战士素材」 |
| 刀风还是「原地闪一下」 | 走的是 `Spin`（判定框面积 ≥ 6）或旧代码 | 检查该 `AttackData` 的 `hitboxSize`，连击三段都应 < 6 |
| 刀风斜着乱飞 | `Warrior_SlashArc` 没紧贴裁切（画布还留白），旋转轴偏了 | 重跑切图脚本，看自检里那条 `189x189` |
| 挥剑却在放法师弹 | `PlayerAttacker.attackData` 是远程资产，或职业 `basicAttack` 是远程 | 跑「生成三段连击」，它会按职业模板纠正 |
| 连击接不上，永远第一段 | `comboWindow` 太小，或 `comboAttacks` 有空槽 | 跑自检看「三段连击已接」 |
| 脱下武器后攻击变回魔弹 | `Equipment` 在 `Awake` 里记了旧的出厂攻击 | 已改成首次用时才取（`DefaultAttack()`） |
| 冲刺按了没反应 | `dashCooldown` 还没到，或正在硬直 | 调小 `dashCooldown`；硬直中断是设计 |
| 死亡后还在跑动 | `health.Died` 没订阅上 | 检查 `WarriorVisual.health` 引用 |

## 10. 已知限制

- **只有一套皮**：法师用的也是这套骑士贴图。真正按职业换装要等 `ClassData` 里加一个人物图字段；
- **上挑借了胜利姿势**：素材表里没有专门的撩剑帧，`Warrior_AttackLift.png` 是从举剑胜利帧复制来的，两者长得一样。以后有正稿直接替换这个文件即可，不用改代码；
- **刀风不吃武器形状**：`Warrior_SlashArc` 固定一张，换剑造型时刀风不会跟着变；
- **连击不能取消**：出手后 `attackHold` 期间不能靠移动打断，只有受击/死亡能打断；
- **跑动不是严格循环**：素材里 4 张跑动帧有两张偏正面，凑不出八向循环；
- **受击没有方向**：只有一张受击姿势，背后挨打也是同一个动作；
- **死亡没有解体**：素材里那张躺地帧带披风，直接切换，没有过渡；
- **没有真正的动画资产**：全部走代码状态机。好处是「不按 Play 也能自检」，坏处是没法在 Animator 里可视化调过渡曲线。
