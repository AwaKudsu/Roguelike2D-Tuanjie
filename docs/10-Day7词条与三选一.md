## 2. 数值是怎么生效的（不用改战斗代码一行）

Day 7 没有发明新的数值系统，用的是 `Core/StatTypes.cs` + `Core/CharacterStats.cs` 早就铺好的那套：

```
RelicData.modifiers[]           // StatModifier(StatType, ModifierMode, Value)
        ↓
CharacterStats.AddModifier()    // 记进 _modifiers 列表
        ↓
CharacterStats.Get(StatType)    // 固定顺序：flat * (1 + percentAdd) * percentMul
        ↓
各处的消费点自动读到新值
```

消费点（这些代码本来就写着，加词条就跟着变）：

| 属性 | 谁在读 |
|---|---|
| `Attack` / `CritChance` / `CritMultiplier` | `Combat/DamageCalculator.cs:26-29` |
| `Defense` | `Combat/Health.cs:55` |
| `AttackSpeed` / `CooldownRate` | `Combat/PlayerAttacker.cs:93-94` |
| `MaxMana` / `ManaRegen` | `Core/ManaPool.cs:134` / `:79` |
| `MoveSpeed` | `Player/PlayerController.cs:141` |
| `MaxHealth` | `Core/CharacterStats.cs:180`（`SyncMaxHealthToHealth`） |

**换句话说：想加新词条，只要新建一个 `RelicData` 资产、填几行修饰符，不用碰任何战斗逻辑。**

## 3. 八个出厂词条

| 资产 | 名字 | 稀有度 | 描述 | 实际修饰符 |
|---|---|---|---|---|
| `Relic_SharpClaw` | 锋利的爪 | 普通 | 攻击力 +10 | `Attack, Flat, 10` |
| `Relic_ThickHide` | 厚皮 | 普通 | 最大生命 +30，防御 +8% | `MaxHealth, Flat, 30` + `Defense, Flat, 0.08` |
| `Relic_SwiftBoots` | 疾风靴 | 普通 | 移动速度 +12% | `MoveSpeed, PercentAdd, 0.12` |
| `Relic_DeepWell` | 深井 | 普通 | 最大法力 +30，每秒回蓝 +2 | `MaxMana, Flat, 30` + `ManaRegen, Flat, 2` |
| `Relic_Berserk` | 狂怒 | 稀有 | 攻击力 +25%，但最大生命 -15 | `Attack, PercentAdd, 0.25` + `MaxHealth, Flat, -15` |
| `Relic_KeenEye` | 锐眼 | 稀有 | 暴击率 +12% | `CritChance, Flat, 0.12` |
| `Relic_ColdBlood` | 冷静 | 稀有 | 冷却缩减 +15% | `CooldownRate, Flat, 0.15` |
| `Relic_Overload` | 超载 | 传说 | 攻击力 ×1.4，但冷却缩减 -10% | `Attack, PercentMultiply, 0.4` + `CooldownRate, Flat, -0.10` |

三种 `ModifierMode` 的区别，看 `Get()` 那行公式就明白：

- `Flat` —— 先全加起来
- `PercentAdd` —— 所有百分比加成先加起来，再乘一次
- `PercentMultiply` —— 各自独立相乘（乘法叠加，越堆越猛）

所以「超载」写 `0.4` 表示 ×1.4，而不是 +40% —— 它是独立乘区。

## 4. 界面为什么用代码搭，不是手拖

三选一面板是 `RelicChoiceUI` 在 `Awake()` 里用代码生成的，理由有两个：

1. **中文字形必须靠系统动态字体。** `Font.CreateDynamicFontFromOSFont(new[] { "Microsoft YaHei", ... }, 32)` 创建出来的 `Font` 是运行时对象，**没法序列化进场景**。手拖的话，Text 组件的字体引用在别人机器上大概率变空 → 满屏方块。
2. 12 个 Text/Image 的引用要一个个拖，拖漏一个就是空引用；代码建的话结构永远和代码一致。

面板结构（`sortingOrder = 300`，盖在世界和 HUD 之上）：

```
Canvas (ScreenSpaceOverlay, 1920x1080, match 0.5)
└── Panel            全屏暗幕 RGBA(0,0,0,0.82)
    ├── Title        「选择一项强化」
    ├── Hint         「按 1 / 2 / 3 或点击卡片」
    └── Card_1..3    400x330，间距 50
        ├── Fill     缩进 4px，做出边框感
        ├── Icon     88x88
        ├── Name     词条名
        ├── Rarity   稀有度（普通灰白 / 稀有蓝 / 传说金）
        ├── Desc     描述（自动换行）
        └── Hotkey   「按 1」
```

弹出时 `Time.timeScale = 0`，关闭时恢复原值 —— 面板期间世界是冻结的。

## 7. 排错表

| 现象 | 原因 | 处理 |
|---|---|---|
| **换到下一关画面永久全黑，之后按门也没反应** | 面板构建抛了异常，异常顺着 `RoomChanged` 炸穿 `RoomManager.AdvanceRoutine`：`fader.FadeIn()` 永远跑不到，`_switching` 卡在 true | 已修，见 §8 |
| 按 F5 没反应 | `debugHotkey` 没勾 / 场景里没 `RelicManager` | 看 Hierarchy 有没有 `RelicManager`，重跑菜单 |
| 面板弹了但全是方块 | 系统没有微软雅黑/黑体 | 装个中文字体，或改 `RelicChoiceUI.UiFont` 的字体名数组 |
| 选了词条数值没变 | `stats` 是空的 | 选中 `RelicManager`，把 Player 的 `CharacterStats` 拖进 `Stats` 字段 |
| 面板出来了但敌人还在动 | `Time.timeScale` 没冻住 | 只有 `Show()` 里设了 0，确认面板真是这个组件弹的 |
| 同一个词条反复出现 | `allowDuplicates` 勾了，或者 8 个词条已经快抽干 | 池子抽干时会退化成允许重复，这是防卡死的设计 |
| 进第二间房没弹 | `offerOnRoomChanged` 没勾 / `RoomManager` 没找到 | Console 会打警告 |

## 8. 事故记录：换关黑屏（已修）

**症状**：打完第一间房走进门，画面变成全黑就再也不亮；之后再走到门口毫无反应。

**根因链**（一条链上三个问题，任何一个单独存在都不会这么惨）：

```
RoomManager.AdvanceRoutine
  └─ yield fader.FadeOut()            // 屏幕已经全黑了
  └─ BuildRoom()
       └─ RoomChanged?.Invoke()        // ← 事件在这里回调
            └─ RelicManager.OnRoomChanged
                 └─ RelicChoiceUI.Build()
                      └─ (RectTransform)transform   // ← 抛 InvalidCastException
  └─ yield fader.FadeIn()             // ← 永远执行不到：协程被异常终止了
  └─ _switching = false               // ← 也执行不到，门从此失效
```

那个 `(RectTransform)transform` 是罪魁祸首：`EnsureUI()` 用 `new GameObject("RelicChoiceUI")` 建物体，挂的是**普通 Transform**，强转成 `RectTransform` 会抛异常（不是返回 null）。

**四处修复**：

1. `RelicChoiceUI.Build()` —— 改成 `transform as RectTransform`，拿不到只警告不中断（子节点自己带 `RectTransform`，照样能搭）
2. `RelicManager.EnsureUI()` —— 建物体时就用 `new GameObject("RelicChoiceUI", typeof(RectTransform))`
3. `RelicManager.OfferChoices()` —— 用 `try/catch` 兜住面板异常并重置 `_offering`（面板坏了不该让换房流程崩）
4. `RoomManager.AdvanceRoutine()` —— 给 `BuildRoom` 加 `try/catch`，**保证 `FadeIn()` 和 `_switching = false` 一定执行**

第 3、4 条是通用的：`RoomChanged` 是给外部订阅的，订阅者（词条、成就、统计……）不应该有能力把换房卡死。
